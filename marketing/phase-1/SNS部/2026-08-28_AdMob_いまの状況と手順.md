## 0-A. 🔴🔴 最優先 — **アカウントを作り直すのは、たぶん逆効果**

CEO 2026-08-28「広告が流れない / アカウントが承認されない。なので**今作り直している**」。

**止めたほうがいい。AdMob と AdSense は「1人につき1アカウント」で、
2つ目を作るのはポリシー違反**。違反すると**両方が停止され、
それまでの支払いも受け取れなくなる**とされている。

そして重要なのは、**それ自体が「承認されない」原因になり得る**こと。
「You already have an AdMob account」で弾かれ続ける事例が実際にある
(2026年に、家族名義のもう1つのアカウントが原因で数か月止まっていた例が報告されている)。

→ **いま pub-9002945296291643 と pub-3780127762345373 が両方生きているなら、
それが「承認されない」の第一候補。** 新しく作るほど遠のく。

**例外**: 別の法人・別の事業体として持っている場合は正当。
**pub-9002 が誰の名義か**をまず確かめてほしい。

### 承認されない理由は「不明」ではなく、見る場所がある

AdMob → **お支払い(Payments)→ 確認(Verification)**:

| 見るところ | 何が分かる |
|---|---|
| **本人確認(Identity verification)** | 政府発行の身分証の提出状況。**求められてから45日で広告が止まる** |
| **住所確認(Address verification / PIN)** | 収益が $10 に達すると郵送される PIN の入力状況。収益0ならまだ来ない(これは承認とは別) |
| **お支払いプロファイル** | 税情報・受取人情報の不備 |
| **メール** | 承認されなかった場合は**メールで通知される**。届いていないか探す |
| AdMob ホーム上部の帯 | 「アカウントを確認中」「対応が必要」などの指示 |

よくある不承認の理由は **(1) 申込時の情報が実際と違う (2) 無効なクリック等の不審な挙動
(3) 支払い情報・PIN の設定が未完了**。

### 私の意見(結論)

1. **新しいアカウントを作る手は止める。** 増やすほど承認が遠のく形をしている。
2. **どちらか1つに寄せる。** アプリが入っているほうを残し、**もう片方は閉じる**。
3. 閉じたうえで **AdMob のサポートに問い合わせる**(重複が解消されたことを伝える)。
   状態が「確認中」で止まっているのは、こちらから動かないと動かないことがある。
4. **広告が出ないこと自体は、いまの最優先課題ではない。**
   Play で配信中の版は**広告が入っていない**ので、直しても収益は
   「ユーザーがいない × 広告」でゼロのまま。
   **リーチが先**(TikTok の数字を読む)で、広告はその後で効いてくる。

## 0. 🔴 パブリッシャー ID が2つある(上と同じ話の、技術面)

もらったスクリーンショットの AdMob は、app-ads.txt にこう書けと言っている:

```
google.com, pub-3780127762345373, DIRECT, f08c47fec0942fa0
```

**アプリと公開中の app-ads.txt は、全部これとは別の ID になっている:**

| どこ | 値 |
|---|---|
| AdMob が指示している pub ID | **pub-3780127762345373** |
| 公開中の app-ads.txt | pub-**9002945296291643** |
| アプリに焼かれている App ID | `ca-app-pub-`**9002945296291643**`~1195899268` |
| バナーのユニット | `ca-app-pub-`**9002945296291643**`/4334445334` |
| リワードのユニット | `ca-app-pub-`**9002945296291643**`/7956060372` |

スクショの文言も **"your details don't match the information in your AdMob account"**
= **app-ads.txt の中身が、AdMob アカウントと一致していない**、と言っている。

**これが「確認できない」の直接の原因。** そして
**「no-fill(広告が出ない)」の説明にもなる** — アプリが名乗っている App ID が
別アカウントのものなら、そのアカウントに紐づく在庫は返ってこない。

### CEO に確認したいこと(これだけ)

**アプリ "TorisCollection (Android)" が登録されているのは、どちらのアカウントですか。**

スクショを見るかぎり **pub-3780127762345373 の中にアプリがある**
(「You successfully added the app to your AdMob account」)。
だとすると、**アプリ側の ID を pub-3780 のものに入れ替える**のが本筋になる。

## 2. 手順(この順番でやる)

### A. まず決める — どちらのアカウントを使うか

AdMob → 左下の歯車 → **アカウント** で、パブリッシャー ID を確認する。
**アプリが入っているほう**が正。

### B-1. pub-3780127762345373 を使う場合(スクショを見るかぎりこちら)

1. AdMob でそのアプリの **App ID** と、**バナー / リワードの広告ユニット**を作る/控える
2. その3つを教えてください。こちらで入れ替えます:
   - `toris_app/android/app/src/main/AndroidManifest.xml` の `APPLICATION_ID`
   - `toris_app/lib/ads/ads.dart` の `AdUnits.banner` / `AdUnits.reward`
3. **versionCode を上げて** AAB を作り直す(2.0.3+11)
4. app-ads.txt を pub-3780 の行だけにする(下の C)

### B-2. pub-9002945296291643 を使う場合

1. AdMob を**そのアカウントに切り替えて**、アプリの確認をやり直す
2. アプリ側は**そのままでよい**(ID は全部そのアカウントのもの)
3. app-ads.txt も**元のままでよい**

### C. app-ads.txt を直す(**CEO の作業**)

`landing/app-ads.txt` は**原稿**で、これを直しても本番には出ない。
公開元は **`AT-KB/aviation-note-site`** の GitHub Pages。
そこの `app-ads.txt` を直して push する。

いま原稿は **両方の行を書いた状態**にしてある(ads.txt は複数の販売者を
並べてよい仕様。移行中はこれが安全):

```
google.com, pub-9002945296291643, DIRECT, f08c47fec0942fa0
google.com, pub-3780127762345373, DIRECT, f08c47fec0942fa0
```

アカウントが決まったら、**使うほう1行だけ**に減らすのが綺麗。

⚠️ スクショの注意書きどおり、**Play に載せているドメインと完全に一致**させること
(`torriscollection.com`)。Play Console 側で見るのは2か所ある:
- アプリの「ウェブサイト」(ストアの設定 → 連絡先情報)= **変更済み**
- **デベロッパー アカウントのウェブサイト**(デベロッパー アカウント → アカウントの詳細)
  = 2026-08-10 時点で `at-kb.github.io` のままだった。**ここも直す**

### D. Play の申告(**CEO の作業**)

広告入りの版を上げる前に:

1. Play Console → **「広告が含まれる」に変更**
2. **データセーフティを出し直す**(INTERNET が復活したため)
3. **ストアのスクショを撮り直す**(バナーと 🎁 が写るようになる)

### E. アップロード(**CEO の作業**)

`release/toris-collection-<version>.aab` を上げて、
**「公開を開始」まで押す**。⚠️ アップロードしただけでは配信されない
(versionCode 7 はこれで丸一日止まっていた)。

## 3. 広告が出るか確かめるとき(no-fill の罠)

- **自分の広告をクリックしない。** 規約違反になる。
- 本番ユニットのまま実機で触るために、`ads.dart` の `kTestDeviceIds` に
  端末を登録してある。**この ID はアプリごとに変わる。**
  別の版で拾った ID を使い回して no-fill になった実績がある(2026-08-21)。
  実機のログで必ず取り直すこと:

```sh
adb logcat -d | grep setTestDeviceIds
```

- 新しいユニットは**作った直後は配信されない**ことがある(数時間〜1日)。
  ID を揃えた直後に出なくても、それだけでは壊れている判断にしない。

## 5. ID を入れ替える作業(決まったら、こちらで即やる)

**アカウントを1つに決めてから**やる。以下は機械的な作業で30分ほど。

| 直す場所 | いまの値 |
|---|---|
| `toris_app/android/app/src/main/AndroidManifest.xml` の `APPLICATION_ID` | `ca-app-pub-9002945296291643~1195899268` |
| `toris_app/lib/ads/ads.dart` の `AdUnits.banner` | `ca-app-pub-9002945296291643/4334445334` |
| `toris_app/lib/ads/ads.dart` の `AdUnits.reward` | `ca-app-pub-9002945296291643/7956060372` |
| `toris_app/pubspec.yaml` の `version:` | `2.0.2+10` → **上げる** |
| `landing/app-ads.txt` | 使うほう1行に減らす |

そのあと `flutter build appbundle --release` → `release/` に置く →
署名の指紋を確認 → CEO が Play へ。

**必要なもの**: 新しい **App ID**(`ca-app-pub-XXXX~YYYY`)と、
**バナー**・**リワード**の広告ユニット ID。この3つだけあれば足りる。
