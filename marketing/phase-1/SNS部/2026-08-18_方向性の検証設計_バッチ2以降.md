## 1. 前提の更新: **売り物が増えている**

5型とフックバンクは Streamlit 版の時点で作られたもので、**その後に入った体験が
入っていない**。CEO が挙げた「鳥と起きる」「鳥と寝る」は、当時**存在しなかった機能**。

| 体験 | 実装 | 既存の型 | 資料に載っているか |
|---|---|---|---|
| 儀式(出会い) | `Ritual` | 型1 The Reveal | ○ 主力型 |
| ラジオ(環境音7層) | `RadioEngine` | 型2 The Quiet Loop | ○ |
| 集める(図鑑) | `GuidePage` | 型1+収集 | △ 断片的 |
| **鳥と起きる(目覚まし)** | `AlarmPage` + ネイティブ | — | **✗ 未収録** |
| **鳥と寝る(スリープ)** | `sleep_mode` 15/30/60/90分 | 型2の変奏 | **✗ 未収録** |
| 餌台の駆け引き | `feeder_chain` | — | **✗ 未収録** |
| なぜ来たか(実データ) | `eco_log` | 型3 Real-Data | ○ |

→ **「鳥と起きる」「鳥と寝る」は、既存の型に無い新しい入り口。**
cozy 層の隣に **睡眠・作業用・目覚まし** という別の検索需要がある。
ここは伸び率の当たりが出る可能性が高い一方、**当てが外れる可能性も同じだけある**ので、
思い込みで本数を割かず、他と同じ条件で1本ずつ測る。

## 2. 何を変えて、何を変えないか(ここが実験の核)

診断書の運用を守る。**バッチの中で変えるのは1つだけ。**

| | バッチ1(実施済) | **バッチ2(提案)** |
|---|---|---|
| 尺 | 8.0秒 | 8.0秒(**変えない**) |
| 構成 | 実画面 0.3秒から / 問い→答え | **変えない** |
| CTA | なし | **変えない** |
| 言語 | 英語 | **変えない** |
| **変える** | **鳥の種**(cardinal / bluejay / sparrow) | **見せる体験** |

バッチ1で分かるのは「この型は通るか」。バッチ2で分かるのは「**どの体験が引くか**」。
ここで言語や尺も一緒に変えると、何が効いたか分からなくなる(診断書§4の指摘と同じ)。

## 3. バッチ2の3本(順序も含めて提案)

冒頭2秒に置くものを、型1〜型2の作法どおりに決める。

### ① 鳥と起きる — `w01_wake`
- 0.0–0.5 目覚ましの時刻画面(7:00 AM)。**動きは秒の変化ではなく寄り**
- 0.5–3.0 暗い画面 → **かすかな1羽の声** → 声が増える(実装どおり:静かに始まって育つ)
- 3.0–8.0 庭が明るくなる / 字幕 **"An alarm that starts as one bird."**
- 冒頭2秒の勝負所: **音が主役**。無音から始めて鳴き声で報酬を出す(型1の音設計)
- 撮影: Wake画面 + 実際に鳴らした画面録画。**アラームは実機で鳴らす必要がある**

### ② 鳥と寝る — `s06_sleep`
- 0.0–0.5 ラジオが鳴っている画面(鳥の点が灯る)
- 0.5–2.0 Sleep 30 min を押す → 画面が暗く沈む
- 2.0–8.0 暗いまま、環境音と鳥だけ。字幕 **"It keeps singing while the screen goes dark."**
- 冒頭2秒: **型2 The Quiet Loop**。ずっと見ていられる/聴いていられる空気
- ⚠️ **画面が暗いだけの絵は「止まって見える」**(バッチ1で潰した失敗の再来)。
  暗転はゆっくり、環境音の波形か小さな光の動きを残すこと

### ③ 儀式 — `r01_ritual`
- 0.0–0.5 木の奥に鳥。**すでに見えている**(隠さない)
- 0.5–5.0 「Listen closely」→ 鳥が枝を移って**手前へ来る**
- 5.0–8.0 出会いのポップアップ。字幕 **"You don't catch it. You wait."**
- 冒頭2秒: **型1 The Reveal**。この商品の一番の瞬間
- 原則1(受動的)がそのまま売りになる唯一の型 — 「捕まえない」が刺さるかを測る

## 4. Launch CM は**別枠**(TikTokのバッチに混ぜない)

CEO案の「Launch CM 的なもの」は、上の3本と**目的が違う**:
- バッチ2 = 伸び率の実験(短く・1体験・同じ型)
- Launch CM = 全体像を伝える(長く・複数体験・型が違う)

混ぜると実験が壊れる。**15〜20秒で別に作り、置き場は X / YouTube Shorts / LP / ストア**。
TikTok に出すなら、バッチ2の測定が終わってから。
※ 素材は既にある(`s04_new_app_1080x1920.mp4` 17.6秒がその原型)。

## 5. 測り方(バッチ1と同じ指標で比べる)

再生数は見ない。**比率で比べる。**

| 指標 | 目標 | なぜ |
|---|---|---|
| 完全視聴率 | 40%以上 | TikTok の最重要シグナル。少数でも比率は安定する |
| 平均視聴時間 ÷ 尺 | 60%以上 | 途中離脱の位置が分かる |

**判定**
```
3本とも20%未満    → 体験の問題ではなく型が劣化している。バッチ1の数字と比べ直す
1本だけ跳ねた     → その体験が入り口。バッチ3で同じ体験の変奏を3本
横並びで差が無い  → 体験は効いていない。次は変数を「言語」に移す(日本語版)
```

⚠️ **バッチ1の実数字が必要。** 完全視聴率が分からないと「跳ねた」の基準が作れない。
CEO に TikTok アナリティクスの3本ぶんの数値をもらうこと。

## 6. 撮影で足りていないもの(先に潰す)

| 必要な素材 | 状態 | 取り方 |
|---|---|---|
| 目覚ましが鳴っている画面 | **無い** | 実機で時刻を数分後にセットして録画 |
| スリープで暗くなる過程 | **無い** | ラジオ再生 → Sleep 15分 → 録画 |
| 儀式で鳥が手前に来る | **無い**(静止画のみ) | 庭に鳥が居る時に録画。**鳥の到来待ちが要る** |
| 裏庭・図鑑・ラジオ | ✅ 収録済 | `tools/video_build/_showcase_src/` |

**儀式は鳥が居ないと撮れない。** 庭に鳥が来るのは実時間の経過後なので、
撮影は「鳥が居るタイミング」を待つ必要がある(作り話の合成はしない=原則4)。

## 7. 進め方

```
1. CEO からバッチ1の完全視聴率をもらう          ← これが無いと比較の基準が無い
2. 足りない素材3つを実機で撮る(目覚まし/スリープ/儀式)
3. バッチ2の3本を書き出す(同じ8秒型)
4. 1日1本で出す。3本出したら数字を見る
5. 跳ねた体験の変奏でバッチ3、跳ねなければ変数を言語に移す
```

`tools/video_build/build_showcase.py` に章を足せば書き出せる(型は共通)。

## 交渉不能5原則との整合

- **受動的**: ③儀式の「捕まえない。待つ」は原則1そのもの。急かす表現は入れない
- **罰しない**: 「今すぐ」「逃すと」等の煽りは使わない
- **声と癒しは無料**: 音を出し惜しみしない。CTA も入れない
- **生態に誠実**: 鳴き声は実録音、出典を画面に出す。合成映像を作らない
- **かわいさ最優先**: どの型も、鳥が主役の画作りを崩さない
