# TikTok 立て直し — 診断と仕様変更（2026-08-08）

作成: SNS部 / 位置づけ: 提案書。仕様変更はCEO承認後に実施。

**一行**: 伸びていないのは「本数が足りない」からではなく、**動画の最初の1秒が静止画に見える**から。
本数を増やす前に尺と構成を作り直す。

## 0. 前提（CEO確認済みの事実）

- 投稿先 = **TikTok**、投稿数 = **2本**、再生は **数十回**。
- 「厳密に0」ではない = **配信は生きている**（審査落ち・シャドウバンではない）。
  数十で止まる = TikTok の初期テストプールを配りきる前に打ち切られた
  = **視聴維持（最初の1〜3秒）のシグナルが悪い**。

---

## 1. 診断（推測ではなく現物の証拠）

### 1-1. 最大の問題: 冒頭3.2秒が「止まって見える」

`post11_reveal` から実際にフレームを抜いた結果:

| 時刻 | 画面 |
|---|---|
| 0.3秒 | 淡い背景 + 黒いシルエット + "Real recording. Who's singing?" |
| 1.0秒 | **0.3秒とほぼ同一**（鳥が6px上下するだけ） |
| 2.5秒 | **0.3秒とほぼ同一** |
| 4.0秒 | ようやく色づいた詳細ドット絵（＝この作品の最大の武器） |

TikTok の視聴者は**1秒未満**でスワイプを決める。最初の3.2秒が同じ絵のままということは、
**視聴者が判断する時間帯に、この動画は「動いていない」**。しかも
**いちばん強いアセット（精密な詳細ドット絵）を、誰も見ていない時間まで隠している。**

`build_quiz.py`（型#4）はさらに深刻で、**答え（＝ドット絵）が出るのは9.0秒**。
波形アニメだけで9秒引っ張る構成は、TikTok では最後まで残らない。

### 1-2. 尺が長すぎる（15秒固定）

リビール／ASMR系は **7〜9秒**が強い。理由は完全視聴率とループ（同じ人が2周見る）で、
これが TikTok の最重要シグナルだから。15秒は「完走されない長さ」で、
**同じ素材でも尺を半分にするだけで完全視聴率は跳ねる。**

### 1-3. 言語とアカウント地域の不一致（**要確認・影響大**）

TikTok の初期プールは**アカウントの地域**で決まる。日本で開設したアカウントなら、
最初に見せられるのは日本のユーザー。そこに**英語オンリーのテキスト**を出せば、
読まずにスワイプされ、そのまま配信が止まる。
現状の動画はすべて英語（"Real recording." / "Who's singing?" / "link in bio"）。

→ **アカウントの地域設定と、実際に届いている視聴者の国**（アナリティクスの「視聴者」タブ）を
CEOに確認してほしい。ここが日本なら、**日本語版を作るのが最優先の一手**。

### 1-4. "link in bio" の外部誘導

低実績アカウントの外部誘導CTAは配信が絞られやすい。CTAは動画から外し、
プロフィール欄に任せる（アプリの宣伝はプロフィールの仕事）。

### 1-5. オリジナル音源のみ＝音経由の発見がゼロ

鳥の声は**商品そのもの**なので基本は譲れない。ただし TikTok では
「音源ページ経由の流入」が主要動線の一つで、そこを完全に捨てている状態。
→ 全部ではなく**一部の本数だけ**、環境音・トレンド音源に乗せて検証する。

## 2. 動画仕様の作り直し（型は変えない。尺と順番を変える）

CEO確定の2フォーマット（#1図鑑リビール / #2食物網ネットワーク）は**やめない**。
壊れているのは中身ではなく**提示の順番**なので、そこだけ直す。

| 項目 | 現状 | 変更後 |
|---|---|---|
| 尺 | 15.0秒 | **8.0秒**（末尾→先頭が繋がるループ） |
| 主役の登場 | 3.2秒（リビール）/ 9.0秒（クイズ） | **0.3〜0.5秒**（最初から色つきで出す） |
| 1本の鳥 | 2羽 | **1羽**（短く・量産しやすく・種ごとにネタが分かれる） |
| 謎かけ | 絵を隠して作る | **絵は見せたまま**、問いをテキストで重ねる |
| テキスト | 英語のみ | **日本語版を主軸**（英語版は別投稿として並行） |
| CTA | 画面に "link in bio" | **入れない**（プロフィールに任せる） |
| 動き | 6px の上下 | ゆっくりズーム＋光の移動（常に変化させる） |

**「絵を隠さないのに、なぜ引っ張れるのか」**: 隠すべきは*絵*ではなく*答え*。
詳細ドット絵は最初から出し、「この声、誰？」ではなく
**「この鳥がいちばん怖いものは？」**のように、**絵を見ていても分からない問い**を出す。

## 3. 新しいネタの源＝今日実装した図鑑プロフィール

本日、GloBI の実データから **好きなもの / 好きな場所 / こわいもの** を図鑑に入れた
（25種に実データの天敵カテゴリ）。これが**そのままSNSのネタ帳**になる。

- 「ハチドリが逃げる相手は？」→ 答え: **クモ**（実際の捕食記録）
- 「カワセミの天敵は？」→ **キツネとフクロウ**
- 「スズメの天敵トップ3」→ **タカ・フクロウ・カラス**

強いのは、**答えが実在のデータで、しかも意外**なこと。作り話の豆知識ではないので原則4に反しない。
25種 × 3項目 = **75本分の問い**があり、3週間の毎日投稿を実データだけで賄える。
（これは新フォーマットの追加ではなく、既存の#1リビール型の中身を差し替えるだけ）

## 4. 頻度（CEOの質問への回答・2026-08-08 修正）

> **修正の経緯**: 当初 SNS部は「1日2本×3週間＝42本」を提案した。これは一般的な
> コールドスタートの定石をそのまま当てた数字で、**この状況には合っていなかった**。
> CEO 指摘「ゴミばっか作っても意味ない。3〜5本やって、伸びるやつを分析して修正すべき」
> を受けて全面的に改める。**壊れていると分かっている型で14本作れば、14本無駄になる。**

**結論: 1バッチ3本（1日1本）。完全視聴率を見て直してから、次の3本。**

### なぜ3本で判断できるのか（ここが要点）

**再生数（カウント）は少数だと読めないが、完全視聴率（比率）は読める。**
100再生でも「40%完走」と「12%完走」は明確に区別がつく。比率は少数でも安定するため、
3本あれば型の良し悪しは判定できる。**逆に再生数だけを見ていると「数十だから分からない」で
止まってしまう。見る指標を変えることが、少数バッチ運用の前提条件。**

見るのは以下2つ（再生数は見ない）:
1. **完全視聴率** — 目標 40%以上
2. **平均視聴時間 ÷ 尺** — 目標 60%以上

### 唯一の条件: バッチの間で投稿を止めない

3本作って1週間空けると、アカウント評価がほぼリセットに戻る。**作り溜めは不要だが、
間隔は空けない**（1日1本のペースを保ったまま、3本ごとに内容を見直す）。

### 最初のバッチで変数を増やさない

バッチ1は **3本とも同じ8秒型・変えるのは鳥だけ**。こうすれば「型が悪いのか、素材が
悪いのか」を切り分けられる。最初から日本語版/英語版/トレンド音源版を混ぜると、
何が効いたか分からなくなる（当初案の欠点）。言語や音源の検証は、型が通ってから。

**プラットフォームは TikTok 1本に絞る。** X/Shorts/Reels は当面 転載のみ。

## 5. 進め方

```
バッチ1: 3本（1日1本・同じ型・鳥だけ変える）
   → 完全視聴率を見る
   全部20%未満  → 型がまだ悪い。冒頭を作り直してバッチ1をやり直す
   差が出た     → 何が効いたか(鳥の派手さ / 問いの内容)を特定

バッチ2: 勝ち筋を伸ばした3本
   → ここで初めて言語や音源など、変数を1つだけ足して検証

以降くり返し
```

**撤退判断**: バッチを4回（計12本）回しても完全視聴率が20%を超えないなら、
**TikTokは向いていない**と判断し、YouTube Shorts（「bird sounds」の検索需要が強く、
長期で効く）へ主戦場を移す。

## 6. 手を動かす順番（承認後）

1. `build_reveal.py` に **8秒ループ・1羽・絵を最初から出す**構成を追加（既存の15秒版は残す）。
2. 図鑑プロフィール（こわいもの）を問いに使い、**バッチ1の3本だけ**書き出す。
   3本とも同じ型で、変えるのは鳥だけ（型と素材を切り分けるため）。
3. 投稿はCEOが手動（TikTok自動投稿は見送り確定済み）。1日1本。
4. 3本の完全視聴率を見てから、バッチ2の内容を決める。
   日本語テキスト版・トレンド音源の検証は、型が通ってから1つずつ足す
   （日本語版はフォントを日本語対応のものに差し替える作業が必要）。

## 7. 承認が必要な事項

1. **尺を15秒→8秒**、**主役を冒頭から出す**構成変更でよいか（型そのものは維持）。
2. 動画から **"link in bio" を外す**ことの可否。
3. **1バッチ3本・1日1本・TikTok集中**の運用でよいか（投稿操作はCEOの手動作業）。

※ 日本語版を主軸にするかは**この提案から外した**。英語ファーストは既定方針であり、
`i18n.py` の既定 `en` として正しく実装されている。言語は型が通ってから、
バッチ2以降で変数1つとして検証する。
