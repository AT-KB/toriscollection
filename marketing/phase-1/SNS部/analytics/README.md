# 投稿の数字を溜めて読む(2026-08-25)

CEO「少しずつ投稿と再生数がたまってきたけどどうしようか、分析とか」。

**やることは2つだけ。**(1) 投稿するたび台帳に5つの数字を写す。
(2) 読みたくなったらスクリプトを回す。

```sh
py -3 tools/sns_analytics.py
```

---

## 1. 台帳に写す(1本あたり30秒)

`posts.csv` の該当行に、TikTok アプリの
**その動画 → 「…」→ アナリティクス** から次を写す。

| 列 | TikTok での名前 | 例 |
|---|---|---|
| `posted_at` | 投稿日 | `2026-08-26` |
| `views` | 再生数 | `137` |
| `full_rate` | **視聴完了率**(%) | `38` |
| `avg_watch` | **平均再生時間**(秒) | `9.2` |
| `likes` | いいね | `7` |
| `follows` | 新しいフォロワー | `1` |
| `top_country` | 視聴者の地域の1位 | `US` |

`comments` / `shares` / `saves` は**あれば**でいい。空欄で構わない。
数字が入っていない行はスクリプトが黙って飛ばす。

`batch` / `topic` / `style` / `cta` / `seconds` は**もう入れてある**。
新しい動画を足すときだけ書く(`style` は見せ方の区別名)。

⚠️ **数字は投稿から3〜4日空けてから写す。** 初日の完全視聴率は
配信の初速で大きく動くので、翌日に見ると別の数字になる。
**全部を同じ日数で揃える**ほうが比較になる。

---

## 2. 何が出るか

- **1本ずつ**: 完全視聴率と95%信頼区間、平均視聴÷尺、目標(40%/60%)に対する判定
- **全体**: 合計と、撤退判断(12本で20%に届かないか)までの残り本数
- **バッチ / 題材 / 見せ方 / CTA ごと**の比較
- **f01 vs g05** と **f02 vs g06** — 字幕が一字一句同じで絵だけ違う組。
  **変数が1つの比較はここだけ**なので、いちばん信用できる

---

## 3. ⚠️ この道具がいちばん言いたいこと — **たいてい「まだ読めない」と出る**

これは不具合ではない。**再生100前後では、完全視聴率 40% と 30% の差は
同じ動画でも普通に起きる。** 目で見て「こっちが勝った」と決めると、
雑音に方針を振り回される(`02_SNS部.md`「n=100 で方針を変えない」)。

なので完全視聴率には Wilson の95%信頼区間を付けて、
**区間が重なっているあいだは「まだ差は読めない」としか言わない。**
併せて「見分けるには片方あたり約 N 再生要る」も出す。

体感として:

| 見たい差 | 片方あたり要る再生数(目安) |
|---|---|
| 40% vs 20%(**別物**) | 約 80 |
| 40% vs 25% | 約 150 |
| 40% vs 30%(大きめ) | 約 360 |
| 40% vs 35%(小さめ) | 約 1,470 |

(`sns_analytics.needed_n` を実行して出した値。検出力80%・両側95%)

→ **いまのリーチだと、読めるのは「別物レベルの差」だけ。**
逆に言えば、そのレベルの差なら少数でも出る。出なければ「どれも同じくらい」。

## 4. 数字を見て、何を決めるか

診断書(2026-08-08)と検証設計(2026-08-18)の判定をそのまま使う。

```
全体の完全視聴率が 40% を超えている
    → 型は効いている。本数を増やす。伸びた1本を Spark Ads で数千円押す
      (目的は DL 数ではなく切り分け:
       リーチは伸びるが DL 0 → 掲載情報が悪い / リーチも伸びない → 動画が悪い)

1本だけ明確に跳ねた(区間が重ならない)
    → その体験が入り口。次のバッチはその体験の変奏で3本

横並びで差が読めない
    → 体験は効いていない。次に変える変数は **言語(日本語版)**
      ※ いま13本すべて英語

12本回して 20% を超えない
    → 撤退の検討(型が劣化しているか、チャネルが合っていない)
```

⚠️ **課金は完全視聴率を読んでからにする。** 広告がまだ no-fill で
回収の当てが無く、リテンションも未測定。この状態で量を買うと
「悪い人を大量に買った」で終わる(`02_SNS部.md`)。

## 5. 溜まってきたら足せること(いまはやっていない)

- **プロフィール表示 → ストア → インストール**の3段。TikTok 側で
  プロフィール表示は取れるが、**ストア遷移とインストールは Play Console 側**。
  両方を同じ日付で並べれば、どこで落ちているかが分かる。
  → いまは「100再生で0DLは期待値どおり」までしか言えない
- **投稿時刻・曜日**。列を足して `by_group` に1行足せば同じ形で比較できる
- **視聴者の国**。`top_country` が JP に寄るなら日本語版の優先度が上がる
