# 06_監査 — 全部署に入り込んでチェックする横断機能

対象: 全員。**監査は部署ではなく、全部署の中に入り込む機能。**
成果物を作らず、**「言っていることと、あるものが合っているか」だけを見る。**

CEO 2026-08-21「監査はすべてに入り込んでチェックすべき」。

---

## 0. なぜ横断にしたか(実際に起きたこと)

ストアの掲載文にこう書いてあった:

> **A radio made only of birds you've met.**

**アプリは、会っていない鳥まで鳴らしていた。** 移植で絞り込みが落ちていた。
数週間、**嘘を掲載したまま**配信していた。

誰も捕まえられなかったのは、当時の監査が **コードの中しか見ていなかった**から。
掲載文は SNS部の持ち物で、実装は開発部の持ち物で、**その間を見る人がいなかった。**

原則4「生態に誠実 — 映っていないものを宣伝で言わない」は、
**宣伝を書くときの心得ではなく、検査すべき対象**だった。

## 1. 監査の3つの層

| 層 | 何を見るか | 実体 |
|---|---|---|
| **① コード** | Python の正と Dart が一致しているか | `tools/migration_audit.py` + `logic.json` |
| **② 製品** | 何もしていない人に、何が見えてはいけないか | `toris_app/test/zero_state_test.dart` |
| **③ 主張** | **公に言っていることが、本当にそうか** | §3 の主張台帳 |

**③ が今回できた層。** ①②は開発部の中で閉じるが、③は SNS部・企画部にまたがる。

## 2. 規則の書き方(ここを外すと監査が飾りになる)

1. **個別の grep を増やさない。** 穴が開いた場所を1つ塞ぐだけでは、
   同じ形の穴がまた別の場所に開く。**捕まえたい"種類"**を書く。
2. **わざと壊して、落ちるのを見てから信じる。**
   2026-08-21 に、緩すぎる正規表現(素通り)と文字列一致(誤検出3件)で
   **規則を書いた本人が2回間違えた。**
3. **全部を一度に埋めない。ラチェットにする。**
   いまの未検証数を基準に記録し、**増えたら落とす**。減らすのは自由。
4. **「何を見ていないか」を数字で出し続ける。**
   監査は毎回 `移した: 100(うち突き合わせ無し 35)` と表示する。
   **「監査を通った」は「正しい」ではなく「監査が見ている範囲では正しい」。**

### 3-A. この表の書き方(機械が読むので、守らないと監査が落ちる)

`tools/migration_audit.py` の `claim_ledger_audit()` がこの表を読む。

1. **「検査」欄は、実在するものを名指しする。** 書き方は2つだけ:
   バッククォートの**ファイル名**(`logic_test.dart` / `tools/migration_audit.py`)と、
   **かぎ括弧のテスト名**(「到来の仕組み: 実データ4440通りで Python 版と一致する」)。
   どちらも**実在を機械で確かめる**。片方も無い行は落ちる。
2. **かぎ括弧「」は、テスト名にだけ使う。** ほかの引用は『』。
   「」の中身は Dart のテスト名に**含まれていること**を見るので、
   地の文に「」を使うとテスト名として探されて落ちる。
3. **検査がまだ無い行は、欄に `未整備` と書く**(`検査できない` でもよい)。
   1と2は免除されるが、**書いたファイル名の実在は免除されない**。
   消えた実体をわざと名指しする行は、`migration_audit.py` の
   `CLAIM_REF_GONE` に理由つきで登録する(`URL_DROPPED` と同じ流儀)。
4. **「どこで言っている」に素材(`f01_alarm` 等)を書いたら、§3.5 に行が要る。**
   出すのをやめた素材は取り消し線(`~~`)で囲む。

## 4. 部署ごとに、監査が入る場所

### 開発部
- 実装の前後で `py -3 tools/migration_audit.py` を回し、**exit 0 と問題0**を確認する。
- **画面を足したらゼロ状態テストに1行**足す(`zero_state_test.dart`)。
- Python の関数を移したら、**fixtures かテストで一度は呼ぶ**(呼ばないとラチェットが上がる)。
- **UI 関数の中に条件を見つけたら、関数に切り出す。** 台帳は公開関数しか数えないので、
  中に埋まった条件は**載りようがない**(外部リンクの移植漏れも、ラジオの絞り込みも、これ)。

### SNS部
- **言い切りを書いたら、§3 の主張台帳に足す。** 検査が無い主張は出さない。
- **実装を見てから書く。** 「なぜ来たか分かる」と書きかけて、その欄が字幕の帯に
  隠れて映らないと気づいた例がある(2026-08-18)。
- 数字を出すときは**出典と取得日**を書く。推定なら推定と書く。

### 企画部
- 仕様を変えたら、**その仕様に依存している主張が無いか**を §3 で確認する。
- Python(正)を変えたら **Dart と fixtures も同時に**直す。片方だけは壊れる。
