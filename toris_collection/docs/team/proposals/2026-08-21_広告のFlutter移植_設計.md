# 提案書 — 広告の Flutter 移植（リワード3種 + バナー）

作成: 2026-08-21 / 位置づけ: 設計案。**CEO 判断が要る点を §7 にまとめてある。**

## 0. CEO 決定（この文書の前提）

- **ケージ（かご型餌台）は無料のまま。** `feeder_chain` は触らない。
- 広告リワードは **リス返し / バードフィーダー / 水飲み桶** の3種に絞る。
- **音源ライセンスは取得済み**（CEO 自身が対応）。商用化の障害は無し。
- 広告を Flutter に移植する方向で進める。

## 1. 現状（実際に読んで確かめた）

| | 状態 |
|---|---|
| `toris_core/lib/src/garden_items.dart` | **移植済み**。6種の定義・対象種の絞り込み・6時間判定・加点計算まで全部ある |
| `engine.dart` | `arrivalBonusFn` と `departureBonus` の**引数を受け取る用意はできている**（L279 / L281） |
| `garden_state.dart` の `catchUp` | `placedFeatures: feeders` は渡しているが、**上の2つを渡していない**（L246-268） |
| 画面 | `GardenItem` を呼んでいる箇所が **0件**。つまり**機能として存在しない** |
| 広告 SDK | 未導入（`pubspec.yaml` に `google_mobile_ads` 無し） |

**「移してあるのに誰も呼んでいない」の典型**（引継ぎ §2）。計算は全部あるので、
残りは**配線・状態・UI・SDK**の4つ。

## 2. 3種の効きを実データで測った

`garden_items.target_bird_ids()` を `data.py` に対してそのまま回した結果:

| アイテム | 効果 | Charlotte | Kyoto | 性格 |
|---|---|---|---|---|
| 🌻 バードフィーダー | 到来 **+1.0pp** | **14種** | **13種** | 広く薄く（種子食全般） |
| 🛡 リス返し | 到来 **+3.0pp** | **3種** | **6種** | 狭く厚く（警戒心 ≥0.55） |
| 💧 水飲み桶 | 退去率 **−5pp** | 全種 | 全種 | 呼ばずに**長居させる** |

3種が「広い/狭い/滞在」で綺麗に散っている。**6種のうちこの3つを選んだのは
バランスとして正しい**（残す価値の低い3種＝ハチドリ用は Charlotte 限定、
ニジャーは2種限定、スエットはキツツキ限定で、いずれも狭すぎる）。

## 3. 問題1 — 「バードフィーダー」が無料の開放型とぶつかる

`garden_items` の `feeder` は **「ヒマワリ・混合シードの開放型給餌器」**。
一方 `feeder_chain` の `feeder_open` も **「開放型の餌台」で無料**。
**同じ物が2つある**ことになり、「ケージは無料」の裏で
「開放型は広告」に見える。原則3（癒しは無料）に触れかねない。

### 案 A（推奨）— 広告側を「道具」ではなく「**継ぎ足し**」にする

広告側の `feeder` を **「今日のシードの継ぎ足し」** に読み替える。
置く物が増えるのではなく、**すでにある餌台の中身が今日は豊富**という扱い。

- 生態的に正直（餌が多い → 種子食の鳥が来やすい）。原則4 を満たす。
- 無料の「どの餌台を置くか（顔ぶれの選択）」と、広告の「今日は多め（量）」で
  **役割が重ならない**。8/20 に「量ではなく顔ぶれ」で整理した軸をそのまま使える。
- 餌台を**置いていない**庭では出さない（継ぎ足す先が無い）。

### 案 B — 広告側の `feeder` を落とし、2種にする

いちばん安全だが、CEO が3種挙げた意図から外れる。

## 4. 問題2 — リス返しは「+3.0pp」より **リスを止める**方が正しい

`feeder_chain` はこう動いている:

    開放型の餌台 → リスが来る → 鷹を呼ぶ → 警戒心の高い小鳥が遠のく

**リス返しはまさにこの鎖を断つ道具**。なのに現行仕様は、鎖とは無関係に
「警戒心 ≥0.55 の鳥に一律 +3.0pp」という別勘定になっている。

### 提案: リス返しを置いている6時間は、開放型でもリスが来ない

- 既にある仕組みだけで説明がつく（恣意的な加点を1つ減らせる）。
- **開放型の利点（大胆な鳥）を保ったまま、臆病な鳥が戻る**という
  6時間限定の"いいとこ取り"になり、リワードとして実感が出る。
- かご型に置いても何も起きない（元々リスが来ない）＝ 正直。

⚠️ **これは Python 側の仕様変更**。引継ぎ §1 のとおり
`garden_items.py` と `garden_items.dart` の**両方**を直し、
`tools/logic_fixtures.py` を回して fixtures を作り直す必要がある。

## 5. 選ぶのか、ランダムか

2026-07-09 の CEO 確定仕様は**完全ランダムで1つ付与**。理由は
「AdMob フローをシンプルに保つため」（`ads.py` 冒頭）。

**その理由は Flutter では消える。** Streamlit 版が複雑だったのは
JS → localStorage → ポーリング → クエリパラメータという WebView 特有の
片道経路を通す必要があったからで（`ads.py` の P1/P0 修正）、Flutter では
`google_mobile_ads` のコールバックを直接 await できる。

3種しか無い状態でのランダムは「水飲み桶が出たが、欲しいのはリス返しだった」
が3回に2回起きる。**選ばせる方に戻すことを推奨する**が、確定仕様の変更なので
CEO 判断（§7）。

## 6. 権限と Play 申告（見落とすと審査で止まる）

現行 v7 は **INTERNET 権限を持っていない**（完全オフライン）。広告を入れると:

- `android.permission.INTERNET` が**復活する**
- `com.google.android.gms.permission.AD_ID` が `google_mobile_ads` から入る
- Play Console の**「広告」欄を「広告が含まれる」に変更**
- **データセーフティ**を出し直す（広告 ID の収集・第三者との共有）
- AdMob 側でアプリ登録 → 実ユニット ID 発行（開発中は Google 公式のテスト ID）

**オフラインで罰しない。** 電波が無い・広告が読めないときは、ボタンを静かに
無効にするだけで何も奪わない（原則1・2。`ads.py` の `fail` 方針を踏襲）。

## 7. 原則との整合（全部満たす前提で設計している）

| 原則 | 守り方 |
|---|---|
| 1 受動的 | 見なくても通常の到来確率は変わらない。効果は6時間で消える。急かす表示を出さない |
| 2 罰しない | 読み込み失敗・視聴中断でペナルティ無し。翌日また出る |
| 3 声と癒しは無料 | **ラジオ再生中はバナーを出さない**（Streamlit 版と同じ）。全画面割り込みは実装しない |
| 4 生態に誠実 | 「なぜ来たか」の生態ログに**混ぜない**。別枠のバッジで「今日はこれを置いています」とだけ出す |
| 5 かわいさ | バナーはホーム下部1枚だけ。庭の絵に重ねない |

## 8. 実装の段取り

1. **配線を先に、広告なしで。** `catchUp` から `arrivalBonusFn` /
   `departureBonus` を渡す。`Garden` に `itemPlacement`（itemId + 置いた時刻）と
   `lastClaimDay` を足し、`shared_preferences` に保存。
   → **この時点で「置けば効く」ことをテストで固定できる**（広告は関係ない）。
2. **UI。** 庭の下に「今日の道具」枠。残り時間のバッジ。対象外の土地では
   `itemUnavailableReason()` をそのまま出す。
3. **SDK。** `google_mobile_ads` を追加。テスト用ユニット ID で
   リワード動画 → 成功時のみ `placeItem()`。バナーはホーム下部。
4. **Play 申告**（§6）と実ユニット ID への差し替え。
5. **監査。** `migration_audit.py` の ads 7関数を台帳で消化し、
   `REQUIRED_IN_UI` に**画面から呼ばれていること**を足す
   （引継ぎ §2「同じ種類を次に捕まえる規則を監査に足す」）。
6. **テスト。** `garden_items` は純粋関数なので `tools/logic_fixtures.py` に
   足して Dart と突き合わせる。足したテストは**わざと壊して落ちるのを見る**（§3）。

## 実機で見つけて直したもの（どちらも release でしか出ない）

1. **起動と同時にクラッシュした。** 広告が WorkManager を連れてきて、それが使う
   Room の生成クラス（`WorkDatabase_Impl`）を **R8 が消していた**。Room は
   `Class.forName(名前 + "_Impl")` で引くので、コード上に参照が無い。
   → `proguard-rules.pro` に keep ルール。**debug では再現しない。**
2. **広告が一度も出なかった。** `RewardedAd.load()` の Future は
   **「要求を出した」時点で完了する**（読み込み完了ではない）。待たずに
   `unavailable` を返していた。→ コールバックを `Completer` で待つ（20秒で打ち切り）。

## 実機で確認できたこと

- テストバナーが庭の下に出る。ラジオ再生中は出ない。
- 🎁 を押す → リワード動画 →「報酬を獲得しました」→ 💧 Bird bath を6時間付与。
- **force-stop して開き直しても「6h left」が残る**（保存の往復）。
- 開放型を置くとリスが庭に出て「The squirrel drew a hawk.」が出る。
