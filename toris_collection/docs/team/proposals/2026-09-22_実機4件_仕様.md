## A. 儀式 — 鳥ごとに「基本テンポ」を変える

### A-0. まず、いま何が起きているのか(数えた)

8/28 の commit b0cfe62 で「鳥ごとに自分の番が来た時だけ跳ぶ」(`ritual.dart:157-164`)に
直っている。だが CEO はまだ「同時」と感じている。**理由を数えた**(2万回のシミュレーション、
90秒=360刻み、3羽):

| 見ていること | 現行(全羽 base 10刻み・ゆらぎ ±2) |
|---|---|
| 2羽以上が**同じ刻み**で跳ぶ回数 / 90秒 | **10.1回**(全360刻み中) |
| 3羽が同じ刻みで跳ぶ回数 / 90秒 | **0.36回** |

つまり**現行はもう「一斉」ではない**。それでも時計仕掛けに見えるのは、
**3羽の周期が全員おなじ 2.5秒だから**。位相をずらしても、同じテンポの振り子が3つ
並んでいるだけなので、目は「同じ拍」として拾う。

さらに悪いことに、**現行の位相差はほとんど動かない**。ゆらぎ ±2刻みだと、2羽の位相差は
1歩あたり標準偏差 2刻み(0.5秒)のランダムウォークにしかならず、5歩たっても平均 0.9秒
しか離れず、しかも**戻ってくる**。

> **→ 直すべきは「位相」ではなく「周期」。** 鳥ごとに**基本テンポそのもの**を変える。
> 新案(下表)では quick と calm は1歩ごとに必ず 0.5秒ずつ開き、**5歩で1周期(2.5秒)
> ぶんずれて、そのまま回り続ける**。これが「バラバラに見える」の実体。

### A-1. 決定: 3つの歩き方(スタイル)

`Ritual` は、始まるときに鳥ごとに**スタイル**を1つ割り当てる。
3つのスタイルを**毎回シャッフルして先頭から配る**(鳥が4羽以上なら i mod 3)。
3羽以下なら**必ず全員ちがうスタイル**になる。

| スタイル | 基本間隔 base | ゆらぎ jitter | 立ち止まり確率 | 立ち止まり長 | 間隔の範囲 | 実効平均 | 90秒の歩数 | 成立率 |
|---|---|---|---|---|---|---|---|---|
| **quick(せっかち)** | 8刻み = 2.00秒 | ±2刻み | **0.12** | +8刻み(2.00秒) | 1.50〜2.50秒(止まると 3.50〜4.50秒) | 2.24秒 | **40.3歩** | **98.50%** |
| **steady(ふつう)** | 9刻み = 2.25秒 | ±3刻み | **0.10** | +6刻み(1.50秒) | 1.50〜3.00秒(止まると 3.00〜4.50秒) | 2.40秒 | **37.6歩** | **98.02%** |
| **calm(のんびり)** | 10刻み = 2.50秒 | ±4刻み | **0.00** | — | 1.50〜3.50秒 | 2.50秒 | **36.0歩** | **97.75%** |
| (参考)現行 | 10刻み | ±2刻み | 0 | — | 2.00〜3.00秒 | 2.50秒 | 36.0歩 | 97.78% |

(成立率 = 90秒のあいだに打てる歩数で、手前の枝に2歩とどまるまで到達する割合。
2万回の実測。現行の実測 97.78% は `ritual_test.dart` の言う 97.8% と一致している)

**刻み(`tickInterval` 250ms)・`ticksPerStep` 10・`step` 2.5秒・`maxSteps` 36 は変えない。**
90秒の敷居も、驚き(リス・鷹)の判定も、いままでどおり**全体の時計**で数える
(`ritual.dart:150-154`)。変えるのは**鳥ごとの跳ぶ間隔の作り方だけ**。

### A-2. 間隔の作り方(式)

- **最初に跳ぶ刻み**: `1 + rng.nextInt(base)`(quick 1〜8 / steady 1〜9 / calm 1〜10刻み)
  — 現行の `ritual.dart:136`(`rng.nextInt(ticksPerStep) + 1`)を base に差し替えるだけ。
- **次に跳ぶ刻み**: `いまの刻み + base + rng.nextInt(2*jitter+1) - jitter
  + (rng.nextDouble() < 立ち止まり確率 ? 立ち止まり長 : 0)`、**下限は1刻み**。
- **驚きの直後の再スケジュール**(`ritual.dart:207-209`)も**同じ式**を使う。
  いまは全羽が同じ式なので、驚いたあとに周期が揃ってしまう。

### A-3. なぜこの数値か(制約の満たし方)

**制約は「90秒(36歩)で出会いが成立する割合を 97.8% から実質下げないこと」**
(`ritual_test.dart:43-56`)。ここで効くのは**90秒のあいだに何歩打てるか**だけである。
90秒の敷居は全体の時計で数える(`ritual.dart:150,173`)ので、**テンポを遅くした鳥は
歩数が減り、そのぶん成立率が落ちる**。実測:

| 実効平均間隔 | 90秒の歩数 | 成立率 |
|---|---|---|
| 2.50秒(現行) | 36.0 | 97.78% |
| 2.69秒 | 33.4 | 96.92% |
| 2.74秒 | 32.8 | 96.75% |
| 2.99秒 | 30.1 | 95.63% |

> **→ 決定: どのスタイルも、実効平均を 2.50秒より遅くしない。**
> 遅い鳥を作るのではなく、**速い鳥を作る**ことで差をつける。
> いちばん遅い calm が現行とぴったり同じ(36.0歩・97.75%)なので、**最悪ケースが現状と
> 同じ**になり、3羽のうち少なくとも1羽に会える確率はむしろ上がる。

**「ときどき立ち止まる」を、なぜ速い鳥に付けたか**: 小鳥の実際の動きは
「素早く数歩 → ぴたりと止まって周りを見る」である。速い鳥は歩数に余裕がある
(40.3歩)ので、**止まりの代金を成立率で払わずに済む**。逆に calm に止まりを足すと
33.4歩・96.92% まで落ちる(上表)ので足さない。calm は間隔のばらつき
(1.50〜3.50秒、2.3倍の幅)そのものが「ときどき溜める」に見える。

### A-4. 変えないもの(CEO の問いへの回答)

**前へ進む確率 0.55 / 手前で 0.45、「手前で2歩」= 出会い は変えない。** 理由は3つ:

1. この2つが **97.8% を作っている本体**である(`ritual_test.dart:23-38` の `_stepsToMeet`)。
   触ると分布そのものが変わり、テストの基準値も A-3 の表も全部引き直しになる。
2. CEO の指摘は「**動くタイミング**が同時」であって「近づきにくさ」ではない。
   直す場所が違う。
3. 行きつ戻りつ(0.45)は**警戒心の表現**で、「近づいてきた」の嬉しさを作っている。
   原則5「かわいさ最優先」(来る瞬間)に直接効いている。

**スタイルは種(species)に固定しない。毎回ランダムに配る。** 種ごとに歩き方を固定すると、
「この種はこういう歩き方だ」という**データの裏づけが無い主張**をアプリが出すことになる。
原則4「生態に誠実」(恣意的なものを足さない)の趣旨に照らして、**その回のその1羽の
気分**として扱う。

### A-5. テストの書き換え(開発部へ)

`ritual_test.dart` は実装と同じ式を手で再現しているので、**必ず一緒に直す**。

1. `_hopTicks`(114-124行)を **スタイル引数つき**にする(base / jitter / 立ち止まり)。
2. 「歩く速さの期待値は変えていない」(151-161行)は**期待値が変わるので書き換える**。
   新しい主張: **どのスタイルも90秒で36歩以上打つ**。
   期待値 quick 40.3 / steady 37.6 / calm 36.0(`closeTo(..., 1.0)`)。
3. 「90秒で97.8%」(43-56行)は、固定36歩ではなく**スタイルごとの歩数で回す**形に変える。
   要求: **どのスタイルも > 0.97**(実測 97.75 / 98.02 / 98.50)。
   従来の「> 0.95」も残す(意味が違うので両方あってよい)。
4. 「3羽が同じ刻みで一斉に跳ぶことは、ほとんど無い」(134-149行)はそのまま残す。
5. **追加**: 「3羽以下なら、基本テンポが全部ちがう」。A-0 のとおり、これが今回の
   直しの本体なので、ここが壊れたら元に戻ったのと同じである。

## B. 目覚まし — 鳥の前に「夜明け前の庭」を1分置く

### B-1. 決定(一覧)

| 項目 | 決定 | 根拠 |
|---|---|---|
| 鳴らすもの | **`assets/ambience/wind.mp3` 1層だけ** | B-2 |
| いつから | **設定時刻ちょうど(T)から**。鳥は **T+60秒**に入る | B-3 |
| 環境音のカーブ | 0.00 →(40秒)→ **0.35** で保持 → 鳥の入場後120秒かけて **0.18** へ → 以後固定 | B-4 |
| 鳥のランプ | **据え置き。5分(RAMP_MS)のまま。ただし起点を「鳥の入場」に移す** | B-5 |
| JOIN2 / JOIN3 | **据え置き**(鳥のランプの 1/3・2/3)。実時刻は T+2:40 / T+4:20 | B-5 |
| 自動停止 | **15分 → 16分**(AUTO_STOP_MS) | B-5 |
| 設定項目 | **増やさない**(オン/オフのトグルは作らない) | B-6-7 |

### B-2. なぜ wind 1層だけか

同梱7層(`assets/ambience/`、`pubspec.yaml:73` で丸ごと APK 同梱)から選ぶ。
`_credits.json` により**7層すべて Freesound の CC0** = 商用可。鳴き声側が
「23種のうち商用可は3種だけ」(`BirdAlarmSounds.java` の注意書き)という制約を
抱えているのに対し、**環境音はライセンス上の懸念がない**。

| 層 | 採否 | 理由 |
|---|---|---|
| **wind** | **採用** | 素材そのものが "Wind in pine trees, slow light, **forest**, pink noise"(`_credits.json`)。**夜明け前の庭**そのもの。定常的で立ち上がりが無く、耳障りな要素(McFarlane ら 2020 が名指しした harsh な音)が一切ない。ラジオの既定の環境音も wind(`radio_engine.dart:293`)なので、**ユーザーがこのアプリの音として既に知っている音**である |
| rain | 不採用 | 広帯域のヒスがさえずり(2〜8kHz)を正面からマスクする。目覚ましの主役は**メロディ**(研究1)なので、それを覆う音は置けない。加えて「雨だから寝ていよう」という情景で、起きる方向と逆 |
| stream / lake / waves | 不採用 | 中高域の水音。rain と同じくさえずりをマスクする。waves は寄せては返す**うねり**があり、音量が周期的に上下するので「静かに立ち上げる」カーブが作れない |
| fire | 不採用 | 焚き火 = 夜の情景。パチパチという**過渡音(transient)**があり、研究1が避けるべきとした harsh の側 |
| drips | 不採用 | 洞窟の水滴。**不規則な単発音**で、いちばん人を起こす種類の音。かつ「庭」ではない |

**複数層は重ねない。** 層を重ねるほど広帯域になり、鳥をマスクする。目覚ましは
「聴かせる」ではなく「起こす」道具なので、**さえずりの通り道を空けておく**ことが最優先。

### B-3. なぜ「時刻より前倒し」ではなく「鳥を60秒遅らせる」か

現行の設計はすでに「T = 起床時刻」ではなく「**T = そっと起こし始める時刻**」である
(T+5分で最大音量。`2026-08-11_目覚まし設計` §2 の表)。したがって前倒しはせず、
**T から風、T+60秒から鳥**にする。設定した時刻に**何かが始まる**ことは保たれる。

**60秒の根拠**: 「鳴り出したことが分かる」には、フェードイン(40秒)が終わって
**一定の音量で保持される時間**が要る。40秒 + 20秒 = 60秒。これ以上長くすると
最大音量到達と自動停止が後ろにずれ、寝過ごし側のリスクが増える(B-5)。

> **延ばす場合の規則**: 60秒を延ばすなら、**AUTO_STOP_MS も同じだけ延ばす**。
> 「最大音量で鳴り続ける時間 = 10分」を必ず保つこと(B-5)。

### B-4. 音量カーブ(数値)

環境音の係数は**目覚まし専用の新しい定数**として Java 側に置く。
**ラジオの `kAmbMax`(wind 1.10)/ `ambVol` は一切参照しない**(別系統・別の目的)。

```
時刻          wind        鳥              情景
──────────────────────────────────────────────────────────
T+0:00        0.00 ↗      —               設定時刻。通知が出て、止められる状態になる
T+0:40        0.35        —               「夜明け前」。風だけ
T+1:00        0.35 ↘      0.08 で1羽目    最初のさえずり
T+2:40        （降下中）   2羽目が加わる    JOIN2 = 鳥ランプの 1/3
T+3:00        0.18        （上昇中）       風が退き切る。以後 0.18 で固定
T+4:20        0.18        3羽目が加わる    JOIN3 = 鳥ランプの 2/3
T+6:00        0.18        1.00            全部そろう。起きる
T+16:00       停止                         自動停止(電池)
──────────────────────────────────────────────────────────
```

- **0.00 → 0.35 は40秒の直線**。既存の `tick()`(`BirdAlarmService.java:134-150`、
  STEP_MS = 1秒)に相乗りして1秒ごとに更新する。新しいタイマーは足さない。
- **0.35 → 0.18 は、鳥が入った瞬間から120秒の直線**。以後 0.18 固定。

**なぜ 0.35 / 0.18 か**(素材のラウドネスから計算):
環境音は -23 LUFS、鳴き声は -19 LUFS に揃えてある(`bird_audio_prep.py:33-34`)。

| 時点 | 風の実効 | 鳥の実効 | 差 |
|---|---|---|---|
| T+0:40(風だけ) | -32.1 LUFS | — | — |
| T+1:00(鳥が入る) | -32.1 LUFS | -40.9 LUFS | 風が 8.8dB 上 = **まだ情景。起こさない** |
| T+6:00(最大) | -37.9 LUFS | -19.0 LUFS | **鳥が 18.9dB 上 = さえずりが完全に前に出る** |

研究1(McFarlane ら 2020 / Clocks & Sleep 2020)が言っているのは
「**メロディのある音だけ**が注意の脱落を有意に減らした。リズムだけでは有意差が出なかった」。
つまり**起こす仕事をするのはさえずり**であって、帯域雑音である風ではない。
だから風が先に可聴になっても「耳障りな音で起こす」ことにはならない。
逆に、**起床の瞬間にさえずりがマスクされていたら研究1を裏切る**ので、
上表のいちばん下の行(18.9dB)が**この設計でいちばん大事な数字**である。

### B-5. 寝過ごし対策(ここは絶対に緩めない)

現行は「T+5:00 に最大 → T+15:00 に自動停止」= **最大音量で10分間鳴り続ける**。
競合 Dawn Chorus が「1分で勝手にスヌーズする」で評価を落としている
(提案書 §2)ことへの対策そのものなので、**この10分を1秒も削らない**。

> **→ AUTO_STOP_MS: 15分 → 16分。** 鳥が60秒後ろにずれるので、自動停止も60秒ずらす。
> `wakeLock.acquire(AUTO_STOP_MS + 30_000L)`(`BirdAlarmService.java:102`)は
> 定数から計算しているので自動で追従する。

**RAMP_MS(5分)は据え置き、ただし起点を鳥の入場に移す。** いま `tick()` は
`onStartCommand` の直後に始まる(128行)ので、そのままだと鳥が入った時点で
ランプが60秒ぶん進んでしまい、1羽目が 0.08 ではなく **0.26 で唐突に鳴き出す**。
**`elapsed` の計時は、1羽目を実際に鳴らした瞬間から始める。**
JOIN2/JOIN3 の `postDelayed`(125-126行)も、同じく**鳥の入場を起点に**掛け直す。

### B-6. 壊れ方の指定(目覚ましは信頼性がすべて)

1. **風が読めなかったら、鳥を待たせない。** `assets/ambience/wind.mp3` の
   `openFd` が失敗したら、**遅延0で即座に現行どおりの動き**(T から鳥)にする。
   前置きのせいで目覚ましが60秒遅れる、は**絶対に作らない**。
   (`fromAsset` は例外を握って null を返す作りなので、その null で分岐する)
2. **`SINGING` は、鳥が実際に鳴り出すまで空のまま。** 画面が「まだ鳴いていない鳥」を
   光らせない(`BirdAlarmService.java:74-81` の趣旨をそのまま守る)。
   風は鳥ではないので `SINGING` には入れない。
3. **`RINGING = true` は T から。** 風だけの60秒のあいだも、通知の Stop も
   アプリ内の「止める」も効く(`onStartCommand:95`。止める道が3つあるのは
   2026-08-13 の「止められない」事故の対策なので、この性質は必ず保つ)。
4. 風の `MediaPlayer` も `USAGE_ALARM`(`alarmAttrs()`)で作る。**メディア扱いにしない**
   (2026-08-13 の全ミュート事故と同じ穴)。`setAudioAttributes` → `setDataSource` →
   `prepare` の順を守る。`setLooping(true)`。
5. 資産のパスは **`flutter_assets/assets/ambience/wind.mp3`**
   (`BirdAlarmSounds.assetFor` と同じ前置き)。
6. `onDestroy` の停止・解放(298-305行)に風のプレイヤーも含める。
7. **設定項目は増やさない。** ラジオ側の環境音の設定(SharedPreferences の
   `radio_amb_on` / `radio_amb_vol`)は**読まない**。理由: ラジオで環境音を全部切っている
   人の目覚ましが無音の前置きになってしまい(`radio_prefs_test.dart:50-62` が
   「全部切り」も正しく保存することを保証している = 実際に起きる状態)、
   さらに rain などを選んでいる人はさえずりがマスクされる(B-2)。**目覚ましは
   目覚ましの都合で鳴らす。**

### B-7. 監査台帳への追記(06_監査.md §3)

この変更で外に出せる言い切りが1つ増える。**言い切りを出すなら行を足す**(06_監査.md:83)。

## D. ラジオ — 鳥の音量を、ユーザーが触れるようにする

### D-1. CEO の問いへの答え:「音量メーターは BGM だけにかかってるよね?」→ **その通り**

`radio_page.dart:177` の Slider は `e.ambVol` だけを動かし、
`applyAmbience()`(`radio_engine.dart:559-576`)が `kAmbMax[k] * ambVol` を
環境音のハンドルにだけ適用している。**鳥の音量は `_peak = kDepthGain[depth]`
(`radio_engine.dart:137`)固定で、ユーザーが触れる手段が存在しない**
(`_scale` は睡眠モード専用、`radio_engine.dart:265-273`)。

### D-2. なぜ「全然聞こえない」のか(数字で)

素材のラウドネスから計算すると、**鳥のほうが 7dB 大きいはず**である:

| | 素材 | 係数 | 実効 |
|---|---|---|---|
| 鳥(b3・既定) | -19.0 LUFS | `kDepthGain['b3']` = 0.85 | **-20.4 LUFS** |
| 風(既定) | -23.0 LUFS | `kAmbMax['wind']` 1.10 × `ambVol` 0.55 = 0.605 | **-27.4 LUFS** |

それでも聞こえない。**大きさ以外に4つ原因がある**:

1. **高域が落とされている。** 観察6回未満は必ず b3(`obsToDepth`、`radio_engine.dart:81-85`)で、
   ローパス **4600Hz**(`kDepthFreq['b3']`)+ 残響 wet **0.20**。さえずりの情報は
   2〜8kHz にあり、素材側で 3.5kHz を +5dB 持ち上げてある(`bird_audio_prep.py:41-44`)のに、
   **その上を落としている**。→ **会ったばかりの人ほど聞こえない**構造になっている。
2. **鳴っていない時間が長い。** 2.5〜5.5秒鳴って、3羽なら休符は
   `4.0 × (3/1.2 - 1) = 6.0秒` ±30%(`_restDuration`、`radio_engine.dart:219-224`)。
   1羽あたりの発声比率は約40%。
3. **風は途切れない。** 広帯域の定常音が鳴り続けるので、聴感上の"地面"になる。
4. **録音の隙間に当たる。** `_startSinging`(179-183行)は録音の途中からランダムに
   入る。無音の間(ま)に当たった回は、その2.5〜5.5秒まるごと鳴らない。

### D-3. 決定(4件)

#### D-3-1. スライダーを**2本**にする(新設: Birds)

| 項目 | 値 |
|---|---|
| 変数 | `RadioEngine.birdVol`(double) |
| 範囲 | **0.0 〜 1.0**(Slider の既定の範囲のまま) |
| **既定値** | **0.80** |
| 実際のゲイン | `birdVol × kBirdGainMax`、**`kBirdGainMax = 1.6`**(新しい定数) |
| 既定でのゲイン | 0.80 × 1.6 = **1.28**(現行 1.00 比 **+2.1dB**) |
| 最大 | 1.6(現行比 +4.1dB) |
| 適用箇所 | `BirdVoice._startSinging`(186行)と群れ(197行)、`fadeScale`(271行)の音量に**掛け算で**入れる: `_peak × _scale × (birdVol × 1.6)` |
| 保存 | SharedPreferences `radio_bird_vol`。`restorePrefs` / `savePrefs`(385-403行)に追加。**つまみを離した時だけ書く**(`onChangeEnd`、既存のスライダーと同じ) |
| 即時反映 | `applyBirdVolume()` を新設。**いま鳴いている鳥だけ**に 200ms のフェードで即反映。鳴いていない鳥は次に鳴くときに反映される |

**なぜ 0.80 を既定にするか**: つまみが端に寄っていると「もう上げられない」と見えるので、
**上にも下にも動かせる位置**に置く。0.80 は目盛りの上寄りだが、`kBirdGainMax = 1.6` が
あるので**上げしろが +2dB 残っている**。そして**触らなくても現行より大きい**
(既定で +2.1dB) — CEO はスライダーを探さなくてよい。

**`kDepthGain` は掛け算の内側に残す。**「よく会った鳥ほど手前で鳴く」
(動画字幕 `g03_song` / 監査台帳)は `kDepthGain` の 1.12 / 1.00 / 0.85 の**比**で
成立している。**外側に一律のゲインを掛けても比は変わらない**ので、この言い切りは壊れない。

#### D-3-2. `ambVol` の**既定値**を 0.55 → **0.45** にする
