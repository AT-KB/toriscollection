## 1. 移植の進め方 — 答えは必ず Python から取る

Python(`toris_collection/`)が**ロジックの正**、Flutter(`toris_app/` +
`toris_core/`)が製品。

```
tools/logic_fixtures.py   Python を総当たりで回して JSON に落とす
        ↓
toris_core/test/fixtures/logic.json
        ↓
toris_core/test/logic_test.dart   Dart で同じ答えになるか突き合わせる
```

**手で期待値を書かない。** 4440通りの到来確率も、1480通りの理由文も、
Python を実際に走らせた結果しか置いていない。

片方だけ直すと突き合わせが壊れるので、**Python の側に誤りが見つかったら
両方直して fixtures を作り直す**(例: 「stopped by 1 times」の英語の誤り)。

## 2. 監査(`tools/migration_audit.py`)

167項目(Python の公開関数151 + 画面16)の台帳。`exit 0` が合格。

見ているもの:
1. **関数を移したか** — 宣言があるか(コメントや文字列は剥がしてから探す)
2. **画面に出てはいけないもの** — `Icons.flutter_dash`、日本語、TODO…
3. **画面に無いといけないもの** — `REQUIRED_IN_UI`(2026-08-18 新設)
4. **素材とfixtureの同一性**
5. **`dart test` と `flutter test` を実際に走らせる**

### 監査が2回すり抜けた。その都度、監査を直した

**1回目**(2026-08-15) — 関数の台帳しか見ておらず、画面を一度も見ていなかった。
CEO「なんで監査機能働いてないの？ゴミみたいな初期スクリーンでわかるミスやん」。
→ 画面リントとテスト実行を追加。

**2回目**(2026-08-18) — リントが「**出ていたら間違い**」しか見ていなかった。
実際に漏れた2件はどちらも逆で、**あるべき呼び出しが画面から落ちていた**:
- 図鑑が属レベルの推定を種の事実として出していた(原則4違反)
- 庭を進める処理が前面復帰で呼ばれず、**鳥が来なかった**
→ `REQUIRED_IN_UI` を追加。

**教訓: 監査をすり抜けた不具合が出たら、不具合を直すだけで終わらせない。
同じ種類を次に捕まえる規則を監査に足す。**

### 「移してあるのに誰も呼んでいない」を定期的に洗う

`toris_core` の公開関数を、core / app / 試験のどこから呼ばれているかで分類する。
関数が正しくても**画面が使っていなければ機能は存在しない**。台帳では検出できない。

## 3. テストは「落ちること」を確かめてから信じる

**新しいテストを足したら、必ずコードをわざと壊して、そのテストが落ちるのを見る。**
落ちなければ何も守っていない。

このセッションで実際に確認したもの:
- 留守の時計の据え置き → 元の `lastSeenAt = now` に戻して落ちるのを確認
- Dart と Java の並びの一致 → 順序を入れ替えて落ちるのを確認
- 監査の `REQUIRED_IN_UI` 2件 → 呼び出しを消して exit 1 になるのを確認

## 4. 交渉不能の5原則は、宣伝物にも効く

`docs/team/00_共通サマリ.md` の5原則は、コードだけの話ではない。

| 原則 | 実務での効き方 |
|---|---|
| 1 受動的である | 急かす飾りを足さない(進捗バー・カウントダウン・段の番号)。動画の点滅も遅く |
| 2 罰しない | 記録を減らす機能を**持たない**。生態ログに削除関数が無いことを試験で固定 |
| 3 声と癒しは無料 | 音を出し惜しみしない。CTA も入れない |
| 4 生態に誠実 | **映っていないものを宣伝で言わない**。属レベルは断る。合成の生態を作らない |
| 5 かわいさ最優先 | 代役の絵でも「まず鳥に見えること」 |

原則4は宣伝で何度も効いた。動画の見出しに「なぜ来たか分かる」と書きかけて、
その欄が字幕の帯に隠れて**映らない**ことに気づき、映っているものだけを言う
文言に変えた。

## 5. 動画の作り方(SNS)

### 判明していること

- **尺ではなく詰め込みが問題。** 8秒版が伝わらなかったのは短いからではなく、
  庭・図鑑・ラジオを並べて機能の羅列になっていたから。
  15秒に増やしても、5段の手順にしたら同じく伝わらなかった。
- **テーマは1本、メッセージは2つまで。**(CEO 2026-08-18)
  15秒に4行入れると、読んでいるうちに絵が変わって何も残らない。
- **動く出来事も1つ。** 植物がせり上がる動きと鳥の飛来を同時に入れたら、
  どちらが本題か分からなくなった。
- **字幕の帯は塗りつぶす。** 半透明だと下のUIが透けて読めない。
- **アプリ名は帯の中。** 画面の上に重ねるとアプリのヘッダーとぶつかる。

### 2つの作り方があり、使い分ける

| | 画面録画版 `build_showcase.py` | 組み立て版 `build_concept15.py` |
|---|---|---|
| 中身 | `adb shell screenrecord` の実画面 | PIL で組んだ絵 + **アプリ本物のドット絵** |
| 得意 | 実物であることの説得力 | 見せたい瞬間を狙って作れる |
| 苦手 | 鳥の到来は実時間でしか起きず撮れない。UIが雑音になる | 実画面ではない |

CEO 2026-08-18「必ずしも実機の撮影ではなくていい」で組み立て版が解禁された。
ただし**絵は `toris_app/assets/sprites/` の本物**を使う(宣伝用に描き起こさない)。
図鑑の詳細画(1024px)が使える種は24種。

### 撮影で分かっている制約

- **睡眠モードの画面暗転は録画に映らない。** 実装は本当に暗くしている
  (`setBrightness(0.0)`)が、`screenrecord` はバックライトを記録しない。
- **儀式は庭に鳥が居ないと撮れない。** 到来は実時間待ち。
- **目覚ましは CEO 立ち会いで。** 一度、盲目のタップで CEO の目覚ましの
  選択鳥を変えてしまった(復旧済み)。起きるための設定を勝手に触らない。

## 6. 実機を触るときの作法

1. **先に控える。** `run-as` で `shared_prefs` を読み、退避してから触る。
   セーブコードは復号して中身も確認する(庭・図鑑・会った日数)。
2. **CEO の設定を変えない。** 目覚ましの時刻・鳥、庭の植物、土地。
   検証で変えるなら戻して、**戻ったことを画面で確認**する。
3. **`pm clear` を使わない。** 権限(通知)まで消える。
4. スクリーンショットは**縮小してから読む**。撮る枚数も絞る。
