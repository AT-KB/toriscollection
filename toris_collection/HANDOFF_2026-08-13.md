## 0. いちばん大事なこと

### ブラウザで音を作るのをやめた
ラジオの環境音は、もともと WebAudio でノイズとベルを合成していた。CEO の試聴で
「オンにしても実感できない」「ブラウザで生成した音に聞こえる」と続けて指摘され、
**合成コードを全部消して、Freesound の CC0 録音に置き換えた**
(`radio.py` にオシレータもノイズバッファも残っていない)。

### Flutter 移行の最大のリスクが小さくなった
提案書は「移行の成否はラジオの音響エンジンで決まる」と書いていた。その中身
(ノイズゲート・AGC)は、**鳴らす前に済ませられる**ことが実測で分かった。
移植が難しい処理ではなく、**そもそも持ち込む必要のない処理**だった(→ §3)。

### ⚠️ 未解決: 実機での音の判定が途中
Flutter スパイクは実機で鳴いており、金属音は解消済み。ただし
**環境音の追加候補3つの採否**と**風の素材を差し替えるか**は未決(→ §5)。

## 1. 環境音(現行 Streamlit 版・本番反映済み)

タイルは **雨 / 風 / 小川 / 波** の4種。すべて Freesound の **CC0** 録音。
`toris_collection/static/ambience/` に同梱し、`/app/static/ambience/` から配る。

| タイル | 素材 | 長さ | Freesound ID |
|---|---|---|---|
| 🌧 雨 | Rain Loop 1 | 69s | 584945 |
| 🍃 風 | 松林を渡る light wind | 116s | 715696 |
| 💧 小川 | 岩を回る小さな流れ | 83s | 819768 |
| 🌊 波 | 小石の浜・引き波で小石が転がる | 116s | 277480 |

**既定は「風」だけオン。** 何も鳴っていないラジオより、葉のそよぐ庭に鳥が来るほうが
ポジショニング(アメリカの庭をスマホに)に近い。

### 取得と加工の決まりごと(`tools/freesound_ambience_pull.py`)
- **CC0 のみ。** 広告つき = 商用なので BY-NC は使えない。BY も帰属表示の管理が
  煩雑になるので採らない。ダウンロード時に1件ずつライセンスを機械で検証する。
- **検索結果の1位を自動採用しない。** Freesound の検索は AND ではないので、
  `rain loop` の1位は音楽、`waves loop` の上位は Piano loops だった。
  採用は `PICKS` に **ID で固定**する。差し替えは ID を1行書き換えるだけ。
- **音量を -23 LUFS に揃える。** 2パス loudnorm。**モノラル化は測る前**に行う
  (後にすると、左右が似ていない録音は混ざった時点で小さくなり、波だけ
  -27.9 LUFS で仕上がっていた)。
- **継ぎ目を畳んで消す(loopify)。** 末尾X秒を先頭X秒にクロスフェードで重ね、
  段差のない輪にする。実測でループ点の段差は録音中の通常の変化に埋もれている。
- URL に**中身のハッシュ**を付ける(`amb_wind.mp3?v=58e5dc6f`)。付けないと
  素材を差し替えてもブラウザが古い音をキャッシュから出す。

### やってはいけないと分かったこと
- `freesound_client.get_ambient_path()` には「CC0 が見つからなければ**ライセンス
  指定なしで再検索**」する分岐があった。商用の本アプリでは規約違反になる。削除済み。
- 起動のたびに Freesound API を叩くのもやめた。検索語に birds が入っており
  **鳥入りの録音**を引くことがあった(鳥は主役なので二重になる)。

## 3. Flutter 移行(ステップ0 = 音のスパイク)

`flutter_spike/`。Flutter 3.44.9 stable。Android SDK と JDK は既にあったので、
追加で入れたのは Flutter だけ。

### 移植の壁だったものが、壁ではなかった
| 現行(radio.py の WebAudio) | スパイクでの扱い |
|---|---|
| 鳴く/休むの状態機械、休符で同時発声を ~1.2 羽に保つ | Dart に写した(定数もそのまま) |
| フェード、奥行きによる音量差 | SoLoud の fadeVolume |
| リバーブ(奥行き) | SoLoud の freeverb。b1/b2/b3 で深さを変える |
| **ノイズゲート** | **持ち込まない。** 鳴らす前に `afftdn` で暗騒音を消す |
| **AGC** | **持ち込まない。** 鳴らす前に `loudnorm` で揃える |

`tools/bird_audio_prep.py` で実測(目覚まし用の4録音):

```
          暗騒音(dB)        声と暗騒音の差(dB)     音量(LUFS)
robin   -42.4 → -66.7        26.4 → 46.7        -21.4 ┐
wren    -55.3 → -72.3        37.8 → 49.8        -17.6 ├→ 全部 -19.4
cardinal -75.0 → -89.0       57.2 → 68.4        -19.0 ├
sparrow -49.3 → -60.7        30.4 → 38.6        -19.3 ┘
```

事前処理なら実時間の制約が無いぶん、ゲートより良い方法(FFT による暗騒音除去)が
使える。**AGC がやっていた「揃える」仕事が、事前に、確定的に終わる。**

### 実機で踏んだ罠(同じことを繰り返さないために)

**(1) freeverb はモノラルの音に使えない**
flutter_soloud の注記に明記されている:「freeverb は2チャンネルにしか使えない。
音のフィルタとして使う場合、その音は2チャンネルでなければならない」。
容量のために録音をモノラルにしていたため、**金属的な異音**になった。残響の深さは
鳥ごとに違えてあるので、**残響が深い鳥ほどひどく壊れる** =「なにか1つ音がおかしい」
という聞こえ方になる。→ 鳥の録音はステレオで書き出す。

**(2) 音声を鳴らすたびに作らない**
「鳴くたびに play() して休符で止める」形にすると、止め損ねたぶんが積み上がり、
同じ録音が何重にも重なって膨らむ。**1羽につき音声1本**を使い回し、鳴く/休むは
音量だけで表す。画面に「鳴っている音声の本数」を出してあるので、再発したら分かる
(正常時は 3羽 + 環境音2層 = 5本で張り付く)。

**(3) OneDrive の下ではビルドが落ちる**
同期がビルド中のファイルを掴み、Gradle が中間ディレクトリを消せずに落ちる。
出力先を Gradle 側で変えると今度は Flutter 本体が APK を見つけられない。
**`build` と `.dart_tool` を OneDrive の外へのジャンクションにする**のが正解
(手順は `flutter_spike/README.md`)。

**(4) スパイクの素材は本体と同期させる**
スパイクの環境音が差し替える前の古い素材のまま取り残され、**却下済みの音**を
聴かせてしまった。素材を変えたら両方に反映すること。

## 4. ロジックの移植(ステップ1 開始)

`toris_core/` — **UI を持たない純粋 Dart パッケージ**。Flutter に依存しないので
`dart test` だけで速く回せる。

移植の正しさは**申告ではなく機械で**見る:

| 対象 | 確かめ方 | 結果 |
|---|---|---|
| セーブコード | Python が書いた実物を Dart が読み、**Dart が書いたものを Python が読む**(双方向) | 4件とも一致。文字数も Python 版と完全一致 |
| 群れ・バッジ | Python に総当たりで食わせた答えの表を Dart が再現できるか | 391通り + 13通り すべて一致 |

- **セーブコードの互換は絶対に壊せない。** 進行データはサーバーに無く、
  この文字列としてのみユーザーの手元にある。
- 手で書き写したテストには書き写した人の思い込みも写るので、**答えは Python 側から取る**
  (`tools/save_code_fixtures.py` / `tools/logic_fixtures.py`)。
- Python の `int()` / `float()` の振る舞い(`int(2.7)==2`、`int("2.5")` は例外)を
  写した `py_coerce.dart` を用意。種データは Sheets 由来で型が揃わず、
  **変換の失敗が分岐に意味を持つ**ため。
- 落とし穴: バッジの文言は `t()` を通るので、fixture 生成時の表示言語で変わる。
  コア層は日本語の原文を返す設計なので、生成時に `i18n.set_lang("ja")` が要る。

まだ移していない: `engine.py`(到来確率) / `ecology.py` / `disturbance.py` /
`daily.py` / `absence_loop.py`。

## 5. 環境音の追加(調査済み・**採否は未決**)

CEO の指定で上位3つを候補として取得済み(`static/ambience/_candidates/`)。
本番には**まだ入れていない**。

| 候補 | 素材 | 長さ | 評価 | ID |
|---|---|---|---|---|
| 🔥 焚き火 | campfire | 116s | ★4.2 / **143件** | 40699 |
| 💧 洞窟の水滴 | Water Dripping in Cave | 86s | ★4.8 / **388件** | 177958 |
| 🏞 湖 | LakeWaves | 90s | ★4.7 / 37件 | 326097 |

### ノイズの色(ピンク/ホワイト/ブラウン)は使えるか — 調べた結論

**"色"を作って足すのはやらない。素材を選ぶ物差しとして使う。** 理由:

1. **色の定義は感覚ではなく傾き**。ピンク -3dB/oct、ホワイト 0、ブラウン -6。
   測れる。`tools/spectrum_check.py` を追加した。
2. **グリーン/ブルーは睡眠の文脈では工学的な定義を持たない**宣伝上の呼び名。
   グリーンは「500Hz〜2kHz あたりを持ち上げた"自然っぽい"音」という程度の意味。
   → これを名乗る機能は作らない。
3. **連続再生のノイズが睡眠に効くという証拠は弱い**。Riedy ら(2021, Sleep Medicine
   Reviews)の系統的レビューは 38 件を調べ、**エビデンスの質は GRADE で「非常に低い」**
   と結論している。
4. よく引用される Papalambros ら(2017)は、**脳波を見ながらスローウェーブの山に
   合わせて 50ミリ秒のピンクノイズを撃つ**研究であって、ピンクノイズを流しっぱなしに
   する話ではない。**アプリで再現できない**ものを根拠にしてはいけない。
5. 一方で**自然音そのものの効果は支持されている**。Buxton ら(2021, PNAS)のメタ分析は
   **水の音が「気分が上向く/健康」に最大の効果**、**鳥の声が「ストレス・不快感の低減」に
   最大の効果**と報告している。**この商品の主役(鳥)と、水系のタイル(雨・小川・波・湖)は、
   そのまま裏付けがある。**
6. Gould van Praag ら(2017, Scientific Reports)は、自然音では副交感神経寄りに、
   人工音では逆に振れ、注意課題の反応も自然音のほうが速いと報告している。
   **「合成をやめて録音にする」という今回の判断と同じ向き。**

### 実測(`tools/spectrum_check.py`)

```
amb_rain    -3.1 dB/oct  ピンク          amb_fire   -6.9  ブラウン
amb_wind    -3.7 dB/oct  ピンク          amb_lake   -2.5  ピンク
amb_waves   -4.3 dB/oct  ピンク          amb_drips  +0.9  ホワイト(当てはまり 0.04)
amb_stream  -0.6 dB/oct  ホワイト(当てはまり 0.10)
```

- 手持ち4種のうち**3種は既にピンク近傍**。狙って選んだわけではないが、
  自然音は自然にそうなる(だから研究が「自然音」を支持するのと整合する)。
- **小川だけがホワイト寄りの外れ値**。ホワイトはシャーッとして耳につきやすい帯域配分で、
  長時間の再生には向かない。**差し替え候補の筆頭はここ**。
- 洞窟の水滴も同じくホワイト寄りで、当てはまりも 0.04 と低い(=一直線では表せない
  断続音)。**採るなら「常時敷く層」ではなく「たまに鳴る点」として扱うべき**。
- 焚き火はブラウン寄り(低音が厚い)。鳥の声の帯域とぶつかりにくいので、
  下地としては相性が良いはず。
