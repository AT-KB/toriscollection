# 「鳥が来ない」の正体と、目覚ましの手入れ(2026-08-18)

CEO「なんで到来全然しないの？考えて監査して」から。**エンジンは正しかった。
アプリが動かしていなかった。**

## 1. 監査でまず数字を出した

CEO の土地(Charlotte / 8月 / 24℃)で、Python の実装をそのまま回した。

| 植物 | 来られる種 | 1コマで誰か来る |
|---|---|---|
| 2種 | 4/17 | 23% |
| 4種 | 15/17 | 65% |
| 12種 | 17/17 | 73% |
| 32種 | 17/17 | 91% |

1週間ぶんを使い方別に回した結果(開いたときに庭に鳥が居る率):

| | 1回/日 | 3回/日 | 6回/日 | 24回/日 |
|---|---|---|---|---|
| 植物4種 | 95% | 95% | 94% | 94% |
| 植物16種 | 98% | 98% | 98% | 98% |

**確率の計算は何も悪くない。** 植物が4種あれば、開けばほぼ鳥が居るはず。
それでも来ないのだから、原因は計算の外にある。

⚠️ この監査で自分が最初に出した「来られるのは4種だけ」は**間違い**だった。
植物IDを `flowering_dogwood` と書いたが、実在は `dogwood`。存在しないIDは
食物網に何も足さないので、勝手に痩せた庭を測っていた。
**IDは必ず `data.py` と突き合わせてから使う。**

## 2. 原因① 前面に戻っても、庭が進まない

`GardenPage._boot()` → `catchUp()` は **`initState` からしか呼ばれない**。
`wantKeepAlive = true` なので、タブを移っても作り直されない。
そしてアプリ全体に**ライフサイクル監視が1つも無かった**
(`grep AppLifecycleState` の結果が空)。

つまり:

```
ホームに戻す → 3時間経つ → アプリに戻る
   → Flutter の処理は生きたまま → initState は通らない
   → catchUp が呼ばれない → 庭は止まったまま
```

**OS がアプリを殺すまで、何時間放っておいても鳥は来ない。**
これが「全然しない」の本体。

直し方: `_GardenPageState` に `WidgetsBindingObserver` を付け、
`resumed` で `_advance(g)` を呼ぶ。儀式の最中だけは触らない
(鳥が近づいている途中で庭を作り直さない)。

## 3. 原因② 短い間隔で開くと、留守の時計が巻き戻る

`catchUp()` は5分未満なら0コマ(これは正しい)。ところが最後の
`lastSeenAt = now;` を**無条件で**書いていた。

```
0分 開く → lastSeenAt=0分
4分 開く → 0コマ。なのに lastSeenAt=4分   ← ここで4分が消える
8分 開く → 0コマ。lastSeenAt=8分
   …何度開いても永久に0コマ
```

直し方: **進んだときだけ**時計を進める(`if (last == null || lastTicks > 0)`)。
`Garden.lastTicks` を足して、進んだコマ数が外から見えるようにした。

試験: `garden_state_test.dart`「5分未満で開き直しても、留守の時計は巻き戻らない」。
**わざと元に戻して落ちることを確認済み**(直っているから通る、を確かめた)。

## 4. 目覚ましの手入れ(CEO の3点)

### 「なんでこの4つしか選べないの？」
音は `res/raw/` に置く必要があり(ネイティブの `MediaPlayer` は Flutter の
assets を読めない)、**4本しか入れていなかった**だけ。増やせる。

ただし条件が2つある:
- **商用に使える録音であること** — 鳴き声36件のうち商用可は**6件だけ**
  (american_robin / carolina_chickadee / eastern_bluebird / mozu /
  northern_cardinal / song_sparrow)。残りは NC(非商用)か ND(改変不可)。
- **ドット絵があること** — CEO が「アイコンもほしい」と言っている以上、
  顔が並ばない種は選択肢に置けない。

この2つを満たすのは `eastern_bluebird` だけだったので、**5種に増やした**。
`carolina_chickadee` は音は使えるが**絵が無い**ので保留(絵ができたら足す)。

⚠️ **並びは末尾に足すこと。** KEYS の順序はそのまま
「夜明けのコーラスで加わる順」なので、間に挿すと既に設定している人の
コーラスが変わる。

### 「アイコンもほしい」
`RadioListTile.secondary` にドット絵。絵の無い種は `BirdMark`(鳥のかたちの
代役)に落ちる。**`Icons.flutter_dash` は二度と出さない**(2026-08-15 の指摘)。

### 「ラジオのような表現、鳴いてるトリの名前がピヨピヨ」
ラジオの `_BirdRow` と同じ考え方にした。点が灯り、名前が色づいて
**ゆっくり息をする**(1.4秒で1往復。速い点滅は急かす表示になり原則1に反する)。

**誰が鳴いているかは Dart 側で組み立てない。**
`BirdAlarmService.SINGING` に、実際に `MediaPlayer` を足したときだけ鍵を積み、
`ringingBirds` で返す。予定を先に書くと、まだ鳴いていない鳥の名前が光る
= 画面が嘘をつく(原則4)。順序の決定は `BirdAlarmSounds.chorusKeysAfter`
の一箇所だけにした。

## 5. CEO 判断待ち — Carolina Wren のライセンス

**CEO が実際に使っている目覚ましの鳥**の録音が `CC BY-NC-ND 4.0`。

- **NC** = 非商用。広告を入れた時点で使えない。
- **ND** = 改変不可。`res/raw` の音は元より短く切ってあり(24.89秒 vs 25.46秒)、
  **無料のいまでも本来置けない。**

勝手に外すと CEO の目覚ましが変わってしまうので**触っていない**。
選べるのは「同じ種の商用可の録音に差し替える」か「選択肢から外す」。

試験 `widget_test.dart`「目覚まし音は license_class が commercial の録音だけ」に
`known = {'carolina_wren'}` として**既知の負債**の形で固定した。
差し替えが済んだら known から外す。新しく足す種はこの逃げ道を使わない。

## 6. 直していないこと

  「植えても来ない」に見えていた可能性が高い。①②を直した状態で
  改めて体感を見てほしい。

- Song Sparrow のドット絵(いまは `BirdMark` の代役)。

## 7. 目覚ましの鳥は**選ばせない**ことにした

CEO「そもそも最初に起こす鳥を選ぶ必要はない」。

選択をやめ、**夜明けのコーラスは1つの並びに固定**した:

```
Northern Cardinal → American Robin → Song Sparrow
   0:00               1:40             3:20
```

3羽なのは設計書の決定(研究3「活動的な情景ほど回復効果が高い」)なので**変えていない**。
この3羽は、選択をやめる前から**何も選ばなかった時に鳴っていた既定の組**そのもの。
新しく決め直したのではない。

**副産物: ライセンス問題が消えた。**
CC BY-NC-ND だった Carolina Wren は誰も鳴らせなくなったので、mp3 ごと外した。
Eastern Bluebird(前の指示で足したもの)も使わなくなったので外した。
いま同梱している目覚まし音は3本、**すべて商用可(CC BY-SA)**。
試験の `known` 例外も消した。

消したもの:
- `res/raw/alarm_carolina_wren.mp3`、`res/raw/alarm_eastern_bluebird.mp3`
- `EXTRA_SOUND` / `K_SOUND` の受け渡し一式(Dart → Kotlin → Java)
- `AlarmSetting.sound`、`Alarm.set` の第3引数

⚠️ **並びが2箇所にある**(Java の `KEYS` と Dart の `dawnChorus`)。
ずれると鳴っていない鳥の名前が光るので、**Java を読んで突き合わせる試験**を足した
(`widget_test.dart`「Dart の dawnChorus と Java の KEYS が一致する」)。
わざと入れ替えて落ちることを確認済み。

## 8. 監査の続き — 「移してあるのに誰も呼んでいない」を洗った

`toris_core` の公開関数を、core / app / 試験のどこから呼ばれているかで分類した。

- **どこからも呼ばれない 5件** — `profileFears` / `centrality` 系4件 / `coOccurrenceMatrix`
- **試験からしか呼ばれない 13件** — `garden_items` 系7件(広告未実装。既知)、
  `networkStats` / `simulateWithAddedPlant` / `suggestForBird` ほか

この中から**本物の不具合が1件**出た。

### 図鑑が、属レベルの推定を種の事実として出していた

`predators.py` の但し書き:
> `level == "genus"` は同属の近縁種の記録から採ったもの。表示側で
> 「近縁のなかまの記録」と断る。**黙って種の事実にしない。**

Python の `bird_profile.rows()` は実際に
`(from records of close relatives)` を付けていた。**Flutter は付けていなかった。**
該当は6種(shijukara, kogera, kibitaki, kawarahiwa, jou_bitaki, aoji)。

交渉不能の原則4「生態に誠実」に正面から反する。図鑑に但し書きを足した
(文言は `i18n.py` の出荷済みの英語をそのまま使用)。

**なぜ今まで気づけなかったか。**
データ層は Python と完全に一致していた(`logic_test.dart` が `genus_level` を
突き合わせ済み)。つまり**関数は正しく移植されていて、画面が使っていなかっただけ**。
関数の台帳では原理的に検出できない。
