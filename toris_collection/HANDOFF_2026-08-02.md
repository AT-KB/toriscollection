## 3. 運用・環境メモ(次セッションが詰まらないために)

- **git push**: `timeout 60 git push origin main` で通る(このセッションは認証キャッシュ有効)。ハングしたらCEOに自分の端末から push を依頼(GCMのGUIダイアログがサンドボックスから触れないため)。
- **本番デプロイ**: `toris_collection/` 配下を push すると Render が再デプロイ → **再デプロイ直後は必ずコールドスタート(~30秒)**。splashのロード画面がこれを埋める(想定内)。マーケ素材(`marketing/`)のpushはデプロイに影響しない。
- **Render は Python 3.11**(`render.yaml` の `PYTHON_VERSION=3.11.9`)。f-string式内バックスラッシュはローカル3.14を通っても本番3.11でクラッシュ。push前に走査すること。
- **Python**: 実体は `py -3`(3.14)。Store版 `python`/`python3` はスタブで動かない。ffmpeg は `imageio_ffmpeg`(同梱バイナリ)。動画ビルドは `tools/video_build/`。
- **実機(Pixel 9a / Android 16)**: adb は `C:\Users\kubok\AppData\Local\Android\Sdk\platform-tools\adb.exe`。
  - **ブラインドのタップ操作は不安定**(CEOが端末使用中だと通知やアプリ切替で誤爆する)。
  - **非侵襲の検証は CDP**: WebViewのDevToolsソケット(`adb shell cat /proc/net/unix | grep webview_devtools`)に `adb forward` し、`tools/cdp_check.py`(`suppress_origin=True` でorigin 403回避)でDOMを読む。今回の品質バグ確認はこれで実施。
- **サブエージェント**: セッション上限に当たると数時間使えない(今回14:20 ETにリセット)。当たっている間はメイン(PJ管理)が直接コード編集+検証して進めた。
- **企画部エージェントの注意**: 今回、提案書を書き終えた後の「最終報告」段階でストール(600秒無進捗ウォッチドッグ)した。**ファイル自体は完成していた**ので、成果物はファイルで確認すること(報告が来なくても書けている場合がある)。
