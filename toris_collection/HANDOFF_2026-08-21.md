詳細は `RELEASE_PLAY_2026-08-20.md`。要点だけ:

  `E2:9D:2C:40:...:6C:45:F7` で公開済みと一致することを `keytool` で確認済み。

- **debug だけ `.dev` を足して別パッケージにした**(`applicationIdSuffix`)。
  release を公開済みと同じ ID にした以上、これが無いと開発中のビルドが
  Play 版とぶつかる(`main.dart` 冒頭の但し書きの意図を保つため)。

## 3. データは更新で消えない(実機で確かめた)

検証用の別パッケージで、庭を作り目覚ましをセット → `adb install -r` で更新 →
**画面も `dumpsys alarm` の登録も残っていた。**

保存先は `SharedPreferences`。Android は **applicationId と署名鍵が同じ限り**
更新をまたいで保持する。**この2つを今後変えないこと**が唯一の条件。

⚠️ **6→7 だけは例外。** WebView 版はデータを端末ではなく Web 側に持っていたので、
ネイティブ版には引き継がれない。テスターへの案内が要る。

## 4. ついでに見つけた目覚ましの穴(未修正・v6 も同じ)

**更新では消えないが、次では消える。** 実機で確認:

- **強制終了で登録が落ちる。** `am force-stop` 後、生きた登録は **0件**
  (履歴に `Reason=pi_cancelled`)。なのに画面は「Set for 07:00」のまま。
- **再起動でも落ちる。** `RECEIVE_BOOT_COMPLETED` の権限はあるが**受信する
  Receiver が無い**(manifest のコメントも「受信は今後」)。
- **一度鳴ったら終わり。** 翌日を組み直す処理がどこにも無い。`enabled` は
  true のままなので、画面はセット済みに見え続ける。

公開中の Capacitor v6(`BirdAlarmBridge.java`)も同じ作りなので**悪化はしない**。
直すなら: `met` を prefs に保存 → 登録処理を Context 依存に出す →
`BOOT_COMPLETED`/`MY_PACKAGE_REPLACED` を受ける Receiver。
**毎日鳴らすか単発のままかは仕様変更なので CEO 判断。**

## 5. 広告を Flutter に移植した

設計と実装の記録は
`docs/team/proposals/2026-08-21_広告のFlutter移植_設計.md`(§9 に CEO 決定、
§10 に実装の記録)。ここには**次の人が踏まないための要点**だけ書く。

### 決まったこと

- **ケージ(かご型餌台)は無料のまま。** `feeder_chain` は広告と無関係。
- 広告リワードは **3種**: 🌻 シードの継ぎ足し / 🛡 リス返し / 💧 水飲み桶。
- **バードフィーダーは「継ぎ足し」に変えた。** 元の定義は「開放型給餌器」で、
  **無料の開放型餌台と同じ物が2つある**状態だった。無料側は「どの餌台か=顔ぶれ」、
  広告側は「今日は中身が多め=量」で役割を分けた。
- **リス返しは加点をやめ、鎖を断つ方式にした。** `feeder_chain` の
  `開放型 → リス → 鷹 → 臆病な鳥が遠のく` の鎖を6時間だけ止める。
  ⚠️ **ホワイトオークを植えていると地面の堅果でリスは来る**(バッフルは餌台しか
  守れない)。守れないものを守れると言わない(原則4)。
- 抽選は**完全ランダム**のまま(2026-07-09 の確定仕様を維持)。
- バナーはホーム下部1枚。**ラジオ再生中は出さない**(原則3)。

### 実機でしか出ない罠を2つ踏んだ

1. **起動と同時にクラッシュ。** 広告が WorkManager を連れてきて、それが使う
   Room の生成クラス(`WorkDatabase_Impl`)を **R8 が消していた**。Room は
   `Class.forName(名前 + "_Impl")` で引くのでコード上に参照が無い。
   → `android/app/proguard-rules.pro`。**debug では再現しない。**
2. **広告が一度も出なかった。** `RewardedAd.load()` の Future は
   **「要求を出した」時点で完了する**(読み込み完了ではない)。待たずに
   `unavailable` を返していた。→ コールバックを `Completer` で待つ。

**教訓: 広告まわりは release ビルドを実機に入れるまで、動いたことにしない。**

### Streamlit 版の複雑さは持ち込んでいない

現行は WebView の制約で「JS → localStorage → 1秒ポーリング → クエリパラメータで
トップごとリロード」という片道経路を通していた(`ads.py` の 2026-07-10 P1修正)。
ネイティブは視聴完了のコールバックを直接 await できるので、全部捨てた。

### ⚠️ ここから先は「アプリを更新しないと変えられない」

**WebView 版は広告の出し分けがサーバー側だった**(Streamlit secrets の
`admob_enabled`)。だから**アプリを更新せずに**広告を出したり止めたりできた。

**Flutter 版は広告がアプリに焼き込まれる。** テスト用ユニット→本番用の
切り替えも、出す/出さないも、**必ず新しい AAB を上げないと変わらない。**
`kUseTestAds` を切り替えたら versionCode を上げて再アップロードすること。

## 6. 監査が3回目のすり抜けをした。規則を2つ足した

CEO「なんで前の監査で発見できなかったのよ」。**バグを直しただけで終わらせていた** —
引継ぎ 2026-08-18 §2 の「同じ種類を次に捕まえる規則を監査に足す」をやっていなかった。

### すり抜けた2件と、その理由

| 逃したもの | なぜ見えなかったか |
|---|---|
| `await MobileAds.initialize()` が起動を止めうる | 監査は**シンボルの有無**しか見ていない。待ち切りかどうかという**挙動**は誰も見ていなかった |
| `ITEM_OFFERED`(6種) と `kOfferedItems`(3種) のずれ | 両方に書いたのに `logic_fixtures.py` へ足さなかった。**定数は突き合わせの対象外**だった |

### 足した規則

- **`SHARED_CONSTANTS`** — (Python の定数, Dart の識別子) の組を並べ、
  ① Dart に宣言があるか ② **その値が `logic.json` に載っているか**を見る。
  載っていなければ「両方に書いてもずれに気づけない」として落とす。
- **`MUST_NOT_BLOCK`** — 起動時の初期化に待ち切りが付いているか。

### 規則を書くときに自分で踏んだ落とし穴(2つとも実際に踏んだ)

1. **`\.timeout\(` では弱すぎた。** ファイルのどこかに timeout があれば通る
   ため、**別の待ちに付いていても素通り**した。`initialize\(\)\s*\.timeout\(`
   と、**初期化そのもの**に付いていることを見る形に直した。
2. **文字列一致で fixtures を探して誤検出した。** `json.dumps` の空白の入り方が
   fixtures(indent=1)と違うだけで「載っていない」と言い張った。
   **構造で探す**(`_contains_value`)形に直した。

**規則も、わざと壊して落ちるのを見てから信じること。** 上の2つは、そうしなければ
「動いているつもりの監査」を増やしただけだった。

### ついでに出てきたもの

- **`WATER_SPECIALIST_EXCLUDE` / `kWaterSpecialistExclude` が死にコードになっていた。**
  リス返しの対象種ロジックを消したときの残り。両言語から削除。
- **`ITEM_ORDER` も誰も使っていなかった。** 削除(抽選プールの正は `ITEM_OFFERED`)。
- **`feeder_chain` は Streamlit(app.py)に一度も配線されていない。** Python 側は
  リファレンス実装だけ。そのため Streamlit で餌台に依存する道具(継ぎ足し・リス返し)が
  当たっても**何も起きなかった**ので、`is_available(..., [])` を渡して外した
  (効かない報酬を出さない = 原則2)。Streamlit では 💧 のみになる。

### ⚠️ 消さなかったもの — Streamlit は消せない

CEO の指示は「Streamlit のやつも整理」だったが、**`toris_collection/` は
消せない**。理由は思想ではなく依存:

- `tools/migration_audit.py` が `PY_DIR = toris_collection` を **AST で読んで台帳を作る**
  (`migration_audit.py:32,75,82`)。さらに定数の突き合わせで `import` もする。
- `tools/logic_fixtures.py` が `sys.path` に足して `garden_items` /
  `feeder_chain` などを **import して期待値を作る**(`logic_fixtures.py:15`)。

つまり **Streamlit を消すと、監査と Python↔Dart の突き合わせが丸ごと死ぬ。**
「Python がロジックの正、Flutter が製品」という進め方(引継ぎ 2026-08-18 §1)は
`toris_collection/` が在ることが前提になっている。

同じ理由で残したもの:
- **`toris_collection/designbird/`** — 動画ビルド4本と `xc_marketing_pull.py` が参照。
  `toris_app/assets/sprites/` と 49 枚が同一だが、**参照元が違う**ので両方要る。
- **`flutter_spike/`** — 9.3MB でほぼ複製音源だが、**README を
  `toris_app/README.md` が参照している**(Gradle が落ちる理由)。

### まだ重いもの(CEO 判断)

`.git` が **391MB**。上で外したフレームは**履歴には残る**ので、これ以上減らすには
`git filter-repo` 等での**履歴の書き換え**が要る。リモート(GitHub)に force push
することになり、他の作業コピーと食い違うので、**指示があるまでやらない。**
